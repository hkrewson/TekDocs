# TekDocs 0.3.1 credential-reference evidence

Date: 2026-08-09

Status: **implementation complete and locally certified.** No push, tag, image publication, deployment, Wiki publication, or other external change was performed.

## Delivered scope

- Provider-neutral credential-reference records that store a title, provider identifier, provider-owned link, scope, lifecycle timestamps, and no customer credential value.
- A strict 1Password adapter for canonical Copy Private Links. Public share links, arbitrary URLs, credentials, ports, fragments, duplicate or extra parameters, malformed identifiers, and non-canonical serialization fail closed.
- Separate `credential_references.view`, `credential_references.manage`, and `credential_references.open` permissions through the central policy service, including tenant-, organization-, and collection-scoped custom-role grants.
- MSP and organization routes with scoped managers, entity/scope guards, forced PostgreSQL RLS, sibling-client non-disclosure, archive behavior, and list/search responses that omit the provider URL.
- A same-origin handoff that revalidates the stored destination, emits an audit event with empty metadata, and redirects the authorized user to 1Password. TekDocs does not retrieve, proxy, display, or log the credential value.
- A credential-reference workspace with search, create, edit, archive, external-custody guidance, responsive/accessibility states, and no secret-value controls.

## Security and compatibility boundary

- A Private Link is a pointer, not an access grant. 1Password remains responsible for authentication, vault authorization, unlock, and display.
- The accepted link grammar is inferred from current 1Password Copy Private Link output because a stable machine-readable provider grammar is not published. Provider format changes therefore fail closed until the adapter, tests, and ADR are deliberately reviewed.
- Existing credential links can become stale when an item moves or is deleted. Automated retrieval, provider API credentials, health checks that inspect vault contents, and public shared-copy links remain outside this feature.
- `TD-RISK-020` remains owned through `0.3.10` stabilization for lifecycle, performance, restore, and accessibility recertification alongside inventory.
