# TekDocs 0.9.2: Markdown profile and rebuildable content index

Date: 2026-10-05. Application version is `0.9.2` after issue #101 completed the
first repository-backed authored-content boundary.

## Completed slice

- `tekdocs.content/v1` defines strict portable frontmatter for documents and
  fragments with stable UUID identity, title, properties, taxonomy stable keys
  and optional current structured-topic schema.
- A bounded CommonMark-aware parser recognizes UUID wikilinks in prose without
  interpreting code examples as links.
- The index reads the exact database-accepted Git commit and atomically builds
  nodes, properties, outgoing links, backlinks, findings and indexed-commit
  evidence in PostgreSQL.
- Full rebuilds are deterministic. An already-current commit is an incremental
  no-op unless a forced verification is requested.
- Invalid accepted commits record sorted, sanitized diagnostics and preserve the
  previous indexed commit and last-known-good graph.
- Links resolve only within the exact repository snapshot. Unresolved and
  foreign UUIDs do not disclose another workspace's content.
- Projection tables use tenant/organization/workspace constraints and forced
  row-level security. The API also enforces existing document view/edit policy.
- A management command provides operator-directed indexing and full rebuild;
  managed UI authoring will call the same service in a later checkpoint.

## Validation evidence

- Parser tests cover valid portable metadata, code-literal behavior, malformed
  wikilinks, strict YAML and bounded input.
- PostgreSQL tests prove deletion/rebuild yields the same authorized projection
  and digest, including properties, outgoing links and backlinks.
- Invalid-commit tests prove rejected input cannot replace the last-known-good
  graph and diagnostics do not echo authored values.
- Cross-repository and runtime-role tests prove foreign targets stay unresolved
  and the new tables remain behind forced RLS.
- Authenticated API and anonymous-denial tests exercise the centralized
  document permission boundary.
- Migration drift, OpenAPI generation, lint, type checking, version alignment,
  frontend verification and the repository-wide composed check pass.

## Deliberate limits

No existing database-authored document is migrated. Fragment inclusion,
operational-entity backlinks, managed Git authoring, coexistence migration and
exact-object publication parity remain issues #102–#106. No GitHub remote,
deployment, published image, tag, pilot or independent security assessment is
claimed.

The next implementation boundary is issue #102 in `0.9.3`.
