# Update production to v0.9.9

Status: published images and signed provenance verified; production update is an
operator action and has not been performed by this task.

The release enables published contextual Wiki guides and fixes Tab/Shift+Tab
entry into overlays. Application candidate is
`f52b210b852249f033dfd895dbb5eee96eb89865`; no new schema migration is introduced
relative to the deployed v0.9.8 candidate.

## Install the release receipt and update

From the existing production checkout, inspect `git status --short` first.
Preserve any local source changes rather than discarding them. Fetch the reviewed
tooling branch and select its fetched commit:

```sh
git fetch origin codex/assigned-organization-candidate
git switch --detach FETCH_HEAD
scripts/update-production.sh --release v0.9.9
```

The command uses the existing saved backup configuration. If it requests backup
paths, supply the existing backup-root and separately retained recovery-key file
as documented by its help; do not skip backup merely to continue.

The tooling checkout supplies `scripts/releases/v0.9.9.images`. The updater
selects the tagged application's Compose configuration, verifies revision labels,
deploys the receipt's immutable backend/frontend/renderer digests, checks running
services and records the deployed commit in `.env`. Worker and scheduler use the
same approved backend image. The tooling checkout's HEAD is not the deployed
application identity. See `0.9.9-publication-security-closeout.md` for digests.

## Confirm after the update

1. Confirm the updater reports backup, migrations, readiness and running-image
   verification successful.
2. Open an existing document and asset.
3. Open contextual Help and follow its published guide link.
4. Open Help again and use Tab/Shift+Tab to enter and move among its controls;
   close it and confirm focus returns to the opener.
5. Open an existing diagram if one is available; record not run otherwise.

Report failures with redacted diagnostics. Do not share credentials, private backup
paths, customer identifiers or document contents. Existing restrictions on manual
profile claims still apply; having no other production users does not constitute
a restricted-reader production check.

Do not retag a release or manually replace digests to recover from a failed update.
Retain the encrypted pre-update backup and deployment evidence; use the established
restore procedure if recovery is necessary.
