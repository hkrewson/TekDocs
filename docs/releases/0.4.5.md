# TekDocs 0.4.5 wireless and DNS inventory evidence

Date: 2026-08-11

Status: **implementation and applicable local evidence complete.** No push, tag, image publication, deployment, or other external change was performed. At this release close the circuit/provider slice was still pending; it was subsequently delivered in chronological build `0.4.6`.

## Delivered scope

- Stable exact-Workspace wireless networks with bounded SSIDs, purpose/security/lifecycle posture, hidden and client-isolation controls, and optional site/VLAN/subnet mappings.
- Permission-aware DNS zones and A, AAAA, CNAME, MX, TXT, SRV, CAA, NS, and PTR records with canonical names, zone ancestry, type-specific validation, CNAME conflict prevention, and optional retained IP-inventory links.
- Non-aggregating MSP/client APIs and restrained searchable Wireless and DNS surfaces with create/edit and relevant mapping controls.
- Central network permissions, MFA-backed mutation, forced PostgreSQL RLS, database ownership/canonical/conflict guards, advisory locks, bounded collections, value-minimized audit data, and IDOR/direct-write/property coverage.

## Known boundaries

- Wireless credentials are deliberately not stored. Unknown and password-shaped request fields fail closed; operators should use an external credential reference for access material.
- This is maintained inventory, not a Wi-Fi controller, DNS authority/resolver, live DNS observation, or certificate monitor.
- `TD-RISK-034` is initially mitigated. Recovery and scale moved to `0.4.9`, formal network certification remains `0.5.0`, and live domain/TLS observation remains `0.7.9`–`0.7.11`.
- Circuits, providers, handoffs, contracts, and lifecycle reminders were subsequently delivered in build `0.4.6`; diagrams and NetBox reconciliation remain later slices.
