# TekDocs 0.1.0 identity stabilization evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request or scheduled run.

## Delivered scope

- The bootstrap, invitation, password-recovery, session, profile, MFA, audit, and OIDC behaviors documented in `docs/AUTHENTICATION.md` are the frozen identity contract for the `0.1.x` line. This stabilization release adds no identity feature family.
- The final MFA enrollment corrections are included: setup survives recent reauthentication, the QR code is generated locally with a manual fallback, and refresh loads safe recovery-code counts from the ordinary authenticator inventory without calling the protected code-reveal endpoint.
- `make clean-install-rehearsal` starts all production-shaped services with generated secrets and isolated new volumes, verifies release readiness, complete migrations, schema drift, and the untouched singleton bootstrap state, then removes only its disposable containers, network, volumes, environment file, and directory.
- `make upgrade-rehearsal` now exports the final `0.0.11` source and proves the supported `0.0.11 → 0.1.0` path against a retained PostgreSQL volume.
- Backend runtime and OpenAPI versions derive from the installed Python package. A blocking repository check keeps `VERSION`, Python project metadata, npm package metadata, and the npm lockfile synchronized.
- Version metadata, health responses, OpenAPI, frontend overview copy, roadmap, operator documentation, and release evidence agree at `0.1.0`.

## Verification

- `make check` passed version synchronization, Ruff, mypy across 38 source files, migration drift, OpenAPI drift, frontend lint and type checks, all 47 frontend unit/component tests, coverage thresholds, and the production build using Node.js 24.
- `make test` passed 103 backend tests with the three intentionally PostgreSQL-only concurrency cases skipped by the fast SQLite settings, plus all 47 frontend tests. Backend coverage was 92.50%; frontend statement coverage was 85.85%.
- `make test-auth-abuse` passed 49 authentication tests with the same three PostgreSQL concurrency tests skipped.
- `make test-compose` reported ready at version `0.1.0`, verified Mailpit SMTP delivery and the documented localhost deployment configuration, and passed all 106 backend tests against PostgreSQL with 95.05% coverage.
- `make test-e2e-all` passed all 48 journeys: 16 each in Chromium, Firefox, and WebKit. The suite includes MFA enrollment, a reload after enrollment, recovery-code status, and the existing critical authentication/accessibility workflows.
- `make clean-install-rehearsal` started backend, frontend, worker, scheduler, PostgreSQL, Valkey, and Mailpit from empty isolated volumes; readiness reported `0.1.0`; every migration was applied; no schema drift existed; and the database contained only the unclaimed singleton installation state.
- `make upgrade-rehearsal` passed `0.0.11 → 0.1.0`, preserving the password hash, verified email, tenant membership, encrypted and decryptable TOTP secret, one-time installation state, and append-only audit records with no migration drift.
- `make security` found no known Python or production npm vulnerabilities, Bandit findings, Gitleaks findings, or High/Critical vulnerabilities in the backend, frontend, or pinned Mailpit images.

## Known boundaries

- GitHub Actions, CodeQL, dependency review, and hosted browser artifact retention remain inferred from locally validated workflow definitions until the repository is published and those workflows run.
- A live external identity provider was not available. OIDC still requires operator validation through the final HTTPS proxy and configured provider before rollout.
- The intentional no-bypass MFA recovery policy remains: loss of the sole owner’s authenticator and every recovery code requires a reviewed recovery procedure or known-good backup.
- Tenant-scoped query primitives and the entity/authorization foundation begin in `0.1.1`; `0.1.0` does not claim organization CRUD or general RBAC.
