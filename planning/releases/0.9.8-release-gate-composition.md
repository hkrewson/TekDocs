# 0.9.8 release-gate composition correction

Scope: the version 1 acceptance slice's local upgrade/recovery validation.
Application candidate remains `b6d65fe2b51c03d6ae84a52488d3c9fc50a275cf`;
this change only corrects tooling and records evidence. It does not promote the
historical pinned release manifest or authorize publication.

## Reproduction and decision

`make client-portal-upgrade-rehearsal` reproduced the original aggregate blocker:
`Client-portal upgrade expected current version 0.5.2, found 0.9.8` (exit 2).
This happens before migration. Inspection found seven fixed-destination historical
checkpoints in the current aggregate: client portal, outbox, notifications,
publication control, key publication, placement/audience and monitoring.

The command-plan regression failed seven subtests before the change, detecting
those exact calls in the actual `make -n release-gate` plan. The correction removes
only those seven aggregate prerequisites. All other prerequisites are retained,
including the supported eight-source minor-version matrix, file/diagram upgrade,
supported recovery, repository foundation, recurring-invoice restore and current
feature-specific rehearsals. Historical targets and their guards remain unchanged
and available explicitly; their historical fixture coverage is not represented as
current-candidate runtime coverage.

## Verification

- Plan regression: red before correction, green afterward.
- `make test-automated-security-review-gate`: 88 tests, three expected live skips.
- Actual historical target still rejects the current destination; removing an
  incompatible aggregate call does not weaken that target's historical contract.
- Full local `make release-gate` was run with five PostgreSQL shards at a time.
  Frontend (127 files / 771 tests), static/schema checks, all ten PostgreSQL
  shards, combined coverage (89%), API/browser performance (four browser cases),
  Compose and six frontend routing checks passed. It then stopped at the full
  six-worker browser matrix: 1,176 passed, 12 expected dedicated-performance
  skips and 20 failures in 12.4 minutes. Firefox/WebKit failures include timeouts
  and missing elements; cause remains unknown. No browser assertions changed.
  Later operational prerequisites were not reached in this aggregate run.
- Whole-Wiki checkout validation is blocked by missing required pages in both
  the existing local checkout and a fresh public Wiki clone. This pre-existing
  inventory gap is separate from the updated local Deployment Verification draft.
- Application, migrations, OpenAPI and rehearsal scripts are unchanged.

## Release limitations

runtime result is recorded separately below. Prior exact-application hosted Build,

Publication-bound attestations and current-candidate CSP/COEP disposition remain
open. Wiki instructions are a local draft; no Wiki publication, tag, deployment,
merge or risk-acceptance renewal is performed by this change.
