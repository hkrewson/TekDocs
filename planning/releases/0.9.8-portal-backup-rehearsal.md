# 0.9.8 portal and notification recovery rehearsal

## Scope and acceptance

Restore the portal/notification rehearsal's database, retained media and accepted
Git repositories into isolated clean volumes, retain its original fixture checks,
and verify repository archive identity. No application recovery policy is changed.

## Verified

The original resumed release gate failed starting the restored system. An isolated
replay with migration log capture reproduced `RepositoryReconciliationError:
Accepted repository content is unavailable`. The rehearsal omitted repository
storage while restoring database rows referencing accepted Git commits.

The fix follows the existing recurring-invoice recovery rehearsal: stop the source
backend before capture, create a repository recovery archive, restore it before
starting the backend, and verify it after startup. PostgreSQL restore now exits
on its first error. Failure cleanup captures migration/backend diagnostics.
The temporary container-writable archive directory stays inside a private mktemp
parent and is removed by cleanup.

The complete Docker `portal-notification-backup-rehearsal` boundary passed in the
resumed release gate, including repository archive verification, all original
publication/notification fixture checks and Django system checks. Log:
`/tmp/tekdocs-release-operations-repository-fix.log`.
Shell syntax and whitespace checks passed.

## Limits

This is later validation tooling, not a runtime change or a claim that 05abb13
already contained the fix. No migration, API contract or public user workflow
changed. Supported encrypted recovery is a separate gate. Other older backup
scripts and subsequent local gates remain unverified until their own executions;
this pass is not evidence of a complete aggregate pass.
