# TekDocs 0.1.2 organization records evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- Organizations remain attached to stable MSP-scoped Entity anchors and store optional legal name and website fields.
- Normalized classifications allow one organization to be any unique combination of client, vendor, manufacturer, and partner.
- Owner/MFA-authorized, tenant-scoped list, detail, create, update, and archive APIs use the Entity identifier as the public address.
- Archive-on-delete preserves the Entity and classifications for the future recycle-bin workflow; archived records are excluded from active reads and cannot be mutated through the active API.
- PostgreSQL rejects classification rows whose organization belongs to another tenant.
- Create, update, and archive operations write value-free append-only audit events.
- The Organizations interface supports classification filtering, multi-classification creation, editing, explicit archive confirmation, and responsive loading/empty/error states.

## Verification

- Version synchronization, Ruff, mypy across 43 source files, migration drift, generated OpenAPI drift, and Bandit passed at `0.1.2`.
- The production-shaped PostgreSQL suite passed all 130 tests with 94.65% coverage. The focused organization/isolation gate passed all 23 cases, including direct cross-tenant classification writes.
- Frontend lint and type checks passed; all 54 unit/component tests passed with 85.85% statement coverage, and the Node.js 24 production build completed.
- The Chromium organization create/edit/archive journey passed with no detectable axe violations.
- `make clean-install-rehearsal` started all production-shaped services on new volumes, applied the classification schema and database guard, reported `0.1.2`, found no migration drift, and verified pristine bootstrap state.
- `make upgrade-rehearsal` passed `0.1.1 → 0.1.2`, preserving a pre-existing organization anchor and identity/authentication data while verifying the new fields, classifications, and guard function.
- Pip-audit and npm audit found no known dependency vulnerabilities; Gitleaks found no leaks. The existing dependency set did not change in this slice.
