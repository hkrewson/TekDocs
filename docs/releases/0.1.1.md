# TekDocs 0.1.1 tenant and organization isolation evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- `DataScope` expresses immutable tenant and optional organization identity. Tenant and organization scoped managers require an explicit scope and raise before issuing an unscoped query.
- `Organization` is introduced only as a stable tenant/entity scope anchor. Client/vendor/manufacturer/partner classifications and user-facing CRUD remain scheduled for `0.1.2`.
- Invitation administration, installation membership checks, and invitation lifecycle operations now use the common tenant-scoped query boundary. Anonymous invitation token redemption remains a documented transactional exception because tenant identity is learned from the digest.
- PostgreSQL triggers reject cross-tenant organization anchors, organization-owned entities, and entity links even when model validation is bypassed.
- Transaction-local PostgreSQL helpers define tenant, organization, and organization-mode inputs for future RLS policies. ADR 0006 records the staged non-owner runtime-role and policy activation strategy; `0.1.1` does not claim active table RLS.
- A dedicated negative-isolation suite is part of the local release gate and production-shaped CI runtime check.

## Verification

- Version synchronization, Ruff, mypy across 40 source files, migration drift, and generated OpenAPI drift passed at `0.1.1`.
- The fast backend suite passed under SQLite; the production-shaped PostgreSQL suite passed all 119 tests with 94.50% coverage.
- `make test-isolation` passed all 12 focused scope tests against PostgreSQL, including missing-scope refusal, cross-tenant/client filtering, direct-write trigger bypass attempts, transaction requirements, and RLS helper semantics.
- Bandit scanned the backend with no identified issues.
- Frontend lint, type checks, all 47 unit/component tests, coverage thresholds, and the production build passed in the required Node.js 24 container. The overview visibly reports the `0.1.1` isolation foundation; no organization CRUD workflow is claimed.
- `make clean-install-rehearsal` started every production-shaped service on new volumes, applied every migration and PostgreSQL helper/trigger, reported `0.1.1`, found no schema drift, and verified the untouched bootstrap state before cleaning only isolated resources.
- `make upgrade-rehearsal` passed `0.1.0 → 0.1.1` on a retained PostgreSQL volume, preserving password, verified email, membership, encrypted/decryptable TOTP, installation state, and audit events while verifying the new organization table and RLS helper function.

## Known boundaries

- RLS table policies are intentionally not enabled. Bootstrap, anonymous token redemption, workers, migrations, operator commands, and a non-owner runtime role must be proven before activation.
- Organization classifications, CRUD APIs, and the usable Organizations interface are `0.1.2` scope.
- Hosted GitHub Actions and CodeQL remain inferred until the repository is published and those workflows run.
