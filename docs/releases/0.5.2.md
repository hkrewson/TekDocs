# TekDocs 0.5.2 client portal identity boundary

Date: 2026-08-11

Status: **applicable local slice complete.** No push, tag, published image, deployment, or external security review was performed.

## Delivered boundary

- MSP administrators can issue digest-only invitations bound to one active client organization.
- Accepted client accounts receive a durable exact-organization membership and an explicit `client_portal` session surface.
- Client sessions render a separate portal shell and are centrally rejected from MSP, workspace, inventory, and ordinary document APIs.
- MSP sessions cannot enter portal APIs. Route identifiers never select or change a client user's organization.
- Database constraints and guards reject role/scope mismatches, cross-tenant organizations, non-client organizations, and organization retargeting.
- Client-document browsing is intentionally absent until `0.5.3`.

## Evidence

- Focused PostgreSQL invitation, acceptance, portal-boundary, database-guard, and migration-cycle tests pass.
- Frontend lint, type checking, 194 component tests, production build, accessibility coverage, and bundle budgets pass.
- Migration drift is clean; the reversible migration cycle advances through accounts migration `0016`.
- The exact `0.5.1` production schema upgrades without changing existing MSP memberships or invitations, and the new organization edges remain empty for those historical records.
