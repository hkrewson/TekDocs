# TekDocs 0.4.9 network simplification evidence

Date: 2026-08-11

Status: **implementation and applicable local evidence complete.** No push, tag, image publication, deployment, live NetBox connection, or destructive legacy-data migration was performed.

## Outcome

`0.4.9` narrows TekDocs to lightweight MSP network documentation. New network-device records are extensions of real hardware assets; IP and MAC records can be assigned directly to those assets. Interfaces and VRFs are absent from ordinary UI workflows but remain preserved compatibility data.

## Data and security boundary

- New device creation requires an active hardware asset in the exact MSP or organization Workspace. Application validation and PostgreSQL triggers independently reject missing, foreign, archived, software, reused, or forged asset edges.
- Existing unbacked devices receive an explicit legacy marker. Selecting a hardware asset repairs the record and irreversibly clears that marker through ordinary workflows.
- IP/MAC assignment resolves a same-Workspace hardware asset and is projected only when the caller also has `assets.view`; network access alone cannot become an asset-name oracle.
- Migration backfills direct asset edges only through an exact retained interface → device → hardware-asset chain. It does not match mutable labels and does not remove interfaces, VRFs, or old edges.
- Search/export retain legacy records with explicit labels. MSP routes remain MSP-owned and never aggregate clients.

## Operator behavior

- The Networks navigation focuses on Devices, Racks, VLANs, Subnets, IP addresses, MAC addresses, Wireless, DNS, Circuits, NetBox, and all-record search/export.
- “Add asset-backed device” requires choosing an existing hardware asset. IP/MAC forms assign directly to hardware.
- Existing interface/VRF context is displayed as legacy information when encountered; deeper interface/routing work belongs in NetBox.

## Verification

The frontend suite passes 192 tests, including the asset-backed forms and the absence of ordinary Interface/VRF tabs. The Docker PostgreSQL network gate, migration reversal/drift checks, OpenAPI contract, exact-Workspace permission/IDOR/RLS cases, legacy upgrade rehearsal, and independent backup/restore rehearsal are the blocking evidence recorded at closeout.
