## Verified

- The original image served 1,142,067 uncompressed editor-JavaScript bytes despite
  an Accept-Encoding: gzip request. Routing regression failed for missing gzip
  on both editor JS and CSS, then all six Docker routing tests passed after fix.
- Gzip is configured only inside the existing public `/assets/` static-file
  location. It uses level 6, a 1 KiB floor, JS/CSS/SVG MIME types and Vary. Proxy
  negotiation applies only there; cache lifetime and try_files=404 remain intact.
- Docker checks prove exact decoded-body equality and retained MIME, cache,
  CSP, nosniff, frame and referrer headers, both directly and with a Via header.
  Identity requests work; HTML stays uncompressed and missing chunks stay 404.
- Five corrected-source browser repetitions passed all 20 cases. Mobile legacy
  editor readiness was 3,075–3,126 ms, versus 8,159–8,219 ms in five uncompressed
  local repetitions. Assertions, limits, one-worker execution and zero retries
  remain. This is measured load reduction, not diagnosis of the old timeout.
- Diagnostics retain only fixed phase labels, numeric counters/timings, editor
  presence and allowlisted numeric Chromium metrics. Unit cases reject payload
  retention, preserve distinct repetitions and handle failed or hung probes.
  A failed-download Docker control still failed the original readiness assertion
  and retained evidence. Raw console/error text, URLs, bodies, headers, DOM text,
  screenshots and traces are not copied into the uploaded directory.
- The new workflow has contents:read only, no publication or secrets input, and
  checks out the explicit PR head for diagnostic comparisons. The normal Extended
  job now rejects missing artifacts. Five repetitions are a separate experiment,
  not a release-evidence substitute; any failure fails the experiment.
