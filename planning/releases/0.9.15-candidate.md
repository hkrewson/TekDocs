## Release notes and source review

Documentation previously passed its public entity UUID to the Git content route,
which expects the separate content UUID. The promoted guide failed with a 404
despite an indexed Git copy. Document responses now include read-only `content_id`,
and the reader and repository-editor link use it. The public `id` is unchanged.
Missing identity, unavailable content and a stale index still fail closed without
showing the historical database copy. This adds a response field and keeps the
existing scoped content route and authorization checks.

Same-title Document and Reusable fragment entries are separate composition
parts. An empty raw document-root body can include a fragment holding its text.
The correction requires no content deletion, repair, reindex or additional
promotion. Wiki guidance is drafted in the existing local checkout and preserved
with other unpublished Wiki edits; this authorization does not publish the Wiki.

Bounded maintainer-directed AI-assisted source review found no new release-blocking
defect in the delta since 0.9.14. Review is not an independent assessment.
[Reproduction and validation](../migrations/promoted-document-reader-identity.md)
records the exact failing Docker replay and the identity boundary in ADR 0115.
The API field is read-only; no content-writing or policy path changes.
