# TekDocs 0.7.13

`0.7.13` stabilizes the domain and certificate monitoring boundary without adding a new domain family.

Domain collection now rejects unsuccessful or structurally misleading DNS-over-HTTPS responses and retains CAA counts/digests alongside resolver-reported DNSSEC state. Domain and certificate names use strict IDNA normalization, certificate wildcards match one label only, and certificate leaf, chain, and SAN processing has explicit resource ceilings.

Every successful monitoring run now carries a deterministic canonical evidence digest. PostgreSQL validates successful-run digests, prevents terminal evidence rewrites, and rejects retained-run deletion. Existing `0.7.12` successful runs receive deterministic backfilled evidence during an atomic guarded migration.

Monitoring histories remain capped at 25 entries and now have fixed query-count coverage at 250-run scale. The Domains interface adds accessible table captions, expanded-state relationships, and live error announcements while continuing to use the existing restrained detail workflow. API responses expose CAA summary and evidence digests; raw DNS and certificate payloads remain excluded.

Release evidence includes focused hostile collector tests, the full monitoring/permission/RLS/migration composition, frontend tests, exact `0.7.12` upgrade rehearsal, and independent PostgreSQL/media backup restore. General monitoring-alert delivery through inbox/SMTP remains outside this slice pending a separately authorized recipient-routing design; `0.8.0` owns composed compliance-and-monitoring certification.
