# TekDocs 0.0.1 foundation evidence

Date: 2026-08-07

Status: locally verified; not published or tagged.

## Verified

- `make bootstrap` completed with generated ignored deployment secrets and repeat-safe behavior.
- `make check` passed Ruff, mypy, migration drift, ESLint, TypeScript, Vitest, coverage, and production frontend build.
- `make test-compose` started PostgreSQL, Valkey, Django/Gunicorn, Celery worker, Celery scheduler, and Nginx/React; all services reached healthy state.
- The production-shaped readiness endpoint returned PostgreSQL-ready status through the Nginx proxy.
- Container tests passed on Linux/Alpine, including deterministic PDF output and envelope-encryption rewrap behavior.
- Chromium Playwright passed desktop navigation, mobile navigation, backend readiness, and Markdown source round-tripping against Compose.
- `make security` passed pip-audit, npm audit, Bandit, Gitleaks, and High/Critical Trivy gates for backend and frontend images.
- OpenAPI validation and drift comparison passed; the initial `accounts` and `core` migrations were applied to PostgreSQL.
- Response inspection confirmed CSP, frame denial, MIME sniffing prevention, referrer, and permissions headers at the web boundary.

## Security decisions made during verification

- Cryptography and pytest constraints were raised after current advisory detection.
- React Router was removed from the pre-authentication shell after the package line had no audit-clean version; the shell now uses a small same-origin History API router.
- The Python runtime moved from Debian slim to Alpine after the Debian base exposed unfixed Critical/High packages TekDocs did not need.
- WeasyPrint was replaced by deterministic ReportLab output after its Alpine native text stack segfaulted. Rich publication layout remains a `0.3.0` concern and cannot regress deterministic output or image security.
- The Nginx image upgrades Alpine packages during build so fixed system packages are present even when the upstream image tag lags its repository.

## Known risks and follow-up

- GitHub-hosted workflows are present but cannot be called verified until the repository is published and a pull request executes them.
- The lazy Milkdown editor chunk is approximately 1.15 MB minified. It does not affect the shell entry bundle, but the `0.3.0` editor implementation must reduce unused language and math assets or explicitly approve the cost.
- Local Compose disables HTTPS redirect so developers can use `http://localhost:3200`; production deployment documentation must require TLS termination and `SECURE_SSL_REDIRECT=true`.
- Authentication routes are intentionally closed. Owner bootstrap, invitations, MFA enforcement, recovery, session administration, rate limits, and OIDC belong to `0.1.0` and must pass their abuse suites before any signup path opens.
- Tenant/entity models are foundational only. Scoped query managers, policy service, PostgreSQL row-level protection, client scopes, and negative isolation tests are blocking work for `0.2.0`.
