# TekDocs 0.6.0 controlled client access certification

Date: 2026-08-11

Status: **local certification complete.** No push, tag, image publication, attestation, deployment, hosted workflow, external delivery, or external security review is implied.

## Certified boundary

TekDocs `0.6.0` certifies the composition of:

- distinct MFA-backed publication, approval, withdrawal, correction, and immutable evidence boundaries;
- exact-client invitation and portal identities separated from the MSP application surface;
- fail-closed client-visible STATIC document and artifact projection;
- fixed-schema transactional outbox processing with bounded retries and idempotent receipts;
- permission-filtered MSP/client inboxes that re-authorize content at read time;
- value-minimized SMTP queueing, fixed templates, preferences, batching, digests, quiet hours, metadata-only administration, and audited dead-letter retry; and
- signed bounded seek histories with authorization-preserving scale/query ceilings.

No model, migration, API route, notification topic, secret field, or new product capability is introduced by this certification slice.

## Risk disposition

- `TD-RISK-003`: **met for this critical workflow; recurring owner retained.** The real browser path now includes separate MSP publisher/approver identities, exact-client invitation acceptance, portal projection, the worker-produced inbox, preferences, and withdrawal through the production-shaped proxy/Django/PostgreSQL stack.
- `TD-RISK-039` through `TD-RISK-042`: **certified for the implemented scope with recurring owners.** Separate decisions, client identity, reference-safe projection, transactional/value-minimized delivery, current authorization, forced RLS, database guards, bounded history, upgrade, and recovery remain release-blocking for later changes.
- `TD-RISK-006`, `TD-RISK-007`, `TD-RISK-009`, and `TD-RISK-010`: **not closed by this slice.** The restore and local production-image rehearsals are not supported encrypted recovery, exact published-image provenance, or hosted CI/security evidence.

## Known boundaries

- Client users receive controlled read-only portal access, not broad co-authoring or MSP navigation.
- MSP-owned listing references do not become portal grants. Only approved, current, exact-client organization publications with safe retained entity projections appear.
- SMTP retains an at-least-once crash window after remote acceptance and before local success recording. Provider bounce/DSN ingestion is not implemented.
- Anonymous trust portals, quorum approval, client acknowledgement, hosted multi-MSP tenancy, and supported encrypted/key-loss recovery are outside this release.
