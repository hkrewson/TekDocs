## Decision 1: inline-style CSP allowance

Finding: `TD-DAST-INLINE-STYLE`, medium, owner Maintainer / #38.

The policy permits inline styles for existing layouts and generated diagrams.
That reduces protection against style injection; it does not authorize inline
scripts. Existing same-origin script restrictions, Markdown sanitization and
strict diagram handling remain, but do not eliminate the residual style risk.

Accepted bounded disposition: accept for 05abb13 only, while tracking narrower
style hashes/nonces or a compatible alternative in #38. Review before any next
runtime candidate or **November 12, 2026**, whichever is earlier. A later date is
not proposed. Acceptance does not assert the stronger style policy was tested.

Alternative: require style-policy remediation and compatibility verification
before release, producing a new runtime candidate and fresh validation.

Maintainer decision: **accepted for 05abb13 only**, with review before the next
runtime candidate or November 12, 2026, whichever is earlier.

## Decision 2: absent Cross-Origin-Embedder-Policy

Finding: `TD-DAST-COEP`, low, owner Maintainer / #38.

The candidate does not claim cross-origin isolation through COEP. Existing CSP,
frame restrictions, authorization and renderer isolation remain separate controls;
they are not equivalent to COEP. Adding it requires compatibility review across
OIDC flows, PDF workers, diagrams, fonts and maintained browsers.

Accepted bounded disposition: accept the omission for 05abb13 only, with the same
next-runtime-candidate / **November 12, 2026** review limit. No claim is made that
COEP compatibility or cross-origin isolation has been verified.

Alternative: require COEP implementation and its compatibility suite before
release, producing a new runtime candidate and fresh validation.

Maintainer decision: **accepted for 05abb13 only**, with review before the next
runtime candidate or November 12, 2026, whichever is earlier.
