# TekDocs 0.5.5 permission-filtered notification inbox

Date: 2026-08-11

Status: **applicable local slice complete after the listed gates pass.** No push, tag, published image, deployment, hosted workflow, or external security review was performed.

## Delivered boundary

- The outbox now creates durable, idempotent per-recipient inbox edges for currently eligible MSP staff and exact-client portal accounts.
- Every API read reconstructs value-minimized display copy and typed navigation only after current source, permission, organization, recipient, and surface authorization.
- MSP and portal sessions use separate private/no-store inbox endpoints. Read/unread changes are CSRF protected and scoped to the authenticated recipient.
- PostgreSQL rejects recipient/surface/event retargeting and deletion, validates membership scope, and applies forced tenant RLS.
- Both shells expose a compact notification popover with loading, empty, retry, unread, actionable, and non-actionable states.
- This release sends no new email. SMTP remains `0.5.6`.

## Compatibility

Events already marked delivered by `0.5.4` are retained as historical outbox evidence and are not replayed into the new inbox. Reinterpreting previously consumed events could notify users who were not recipients at event time. New events consumed after the upgrade create inbox entries.

## Evidence

- `make test-notifications` covers recipient projection, current authorization, value minimization, cross-surface denial, reversible read state, idempotency, PostgreSQL identity guards, forced RLS, and frontend behavior.
- `make check` covers lint, types, migrations, OpenAPI, frontend tests/accessibility, production build, version metadata, and bundle budgets.
- `make notification-upgrade-rehearsal` proves the exact `0.5.4` production-image upgrade retains historical data, leaves an already delivered event un-reinterpreted, and projects a new event exactly once.
