# TekDocs 0.3.9 explicit workspace ownership evidence

## Outcome

TekDocs now represents ownership with stable Workspace UUIDs instead of treating a nullable organization foreign key as the owner identity. Each supported one-MSP installation has one MSP Workspace; each organization has one organization Workspace. `Tenant` remains the installation boundary and future hosted seam without changing the supported topology.

Every universal Entity requires a Workspace. Existing MSP-owned and organization-owned Entities are backfilled before the column becomes non-null. Production services pass an explicit Workspace or use the explicit owner-resolution factory; ordinary Entity creation with an omitted Workspace fails rather than defaulting to MSP ownership.

Workspace identities use protected tenant/organization relationships, a fail-closed scoped manager, shape constraints, uniqueness constraints, and an immutable PostgreSQL guard. Entity validation and its PostgreSQL guard require exact tenant/Workspace/organization agreement. Organization archival retains the organization, anchor Entity, Workspace, child Entities, and typed records; physical organization or Workspace deletion cannot orphan ownership.

Transaction-local PostgreSQL scope now carries the Workspace UUID alongside tenant, organization, and mode. Base Entity writes require the bound Workspace. Existing permission-filtered read-only documentation and supplier-catalog projections remain available without widening writes or treating MSP scope as client aggregation.

## Milestone movement

- Attachment-provider hardening, quarantine, asset relationships, bulk operations, and the hostile-file corpus move intact to `0.3.10`.
- CSV import/export moves intact to `0.3.11`.
- Inventory and credential-reference stabilization moves intact to `0.3.12`.
- `0.4.0` remains the certification boundary; no security, isolation, migration, backup, or upgrade gate is compressed.

## Verification

- Migration/model drift, Ruff, mypy, OpenAPI drift, frontend lint/type/component/build gates, and version consistency pass.
- Backend coverage includes explicit-owner creation, missing-owner failure, exact Workspace matching, unique MSP/organization identities, retained ownership after archive, and protected organization deletion.
- PostgreSQL runtime tests bind Workspace scope and retain missing-scope, MSP/client/sibling/cross-tenant, write-check, document projection, and connection-reuse isolation.
- The runtime database validator requires the Workspace identity guard in addition to the existing forced-RLS and control-plane inventories.
