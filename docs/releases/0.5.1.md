# TekDocs 0.5.1 controlled publication distribution

Date: 2026-08-11

Status: **applicable local slice complete.** No push, tag, image publication, deployment, portal access, email delivery, or external security review was performed.

## Delivered boundary

- Immutable STATIC publications now expose explicit `pending_approval`, `published`, `review_due`, `withdrawn`, and `superseded` states derived from an append-only control ledger.
- Client-visible snapshots require approval by a different authorized user. Publishing, approval, and withdrawal are independent MFA-required permissions supported by built-in and scoped custom roles.
- MSP evidence access and future client-portal availability are separate audience projections. Pending, withdrawn, superseded, and MSP-internal publications are unavailable to the client projection.
- Withdrawal records a reason and removes distribution availability without deleting signed Markdown, HTML, manifests, PDFs, retained attachments, or history.
- A correction supersedes its predecessor only after approval. PostgreSQL locking and guards permit only one approved successor while allowing an abandoned or withdrawn attempt to be replaced safely.
- Existing `0.5.0` publications receive historical submitted and approved events during migration, preserving their prior availability semantics.
- Documentation UI and API surfaces display audience availability, decision history, approval/withdrawal controls, and correction state without introducing a portal or notification delivery path.
- Documentation is now route-lazy-loaded; the production shell remains below its existing 500 KiB budget instead of weakening the established performance gate.

## Security and compatibility disposition

- `TD-RISK-039`: **mitigated with recurring owner.** Separation of duties, central scoped policy, non-disclosing IDOR behavior, append-only database guards, forced RLS, advisory locking, and explicit projections are blocking controls for all future portal work.
- Historical approval backfill is a compatibility assertion, not evidence that old content received independent review. Operators should review sensitive client-facing publications before enabling a future portal.
- Client users, portal sessions, invitations, delivery notifications, rejection/quorum workflows, and anonymous access remain out of scope.
