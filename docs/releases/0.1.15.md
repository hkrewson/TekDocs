# TekDocs 0.1.15 foundation stabilization evidence

Date: 2026-08-09

Status: verified locally; hosted GitHub execution remains externally blocked pending explicit repository-publication authorization.

## Delivered scope

- A fixed-shape PostgreSQL reference fixture now creates 100 client organizations, 10,000 distributed reference records, 250 People associations, 50 Sites, 250 Locations, and typed relationships. Six ordinary authorized API reads have a blocking 500 ms p95 ceiling and independent service query-count budgets.
- A representative migration-cycle fixture creates organization, classification, person, site/location, versioned custom-field, relationship, scoped-role assignment, archived-record, and audit state; reverses active RLS migration `0019` to `0018`; reapplies it; and verifies preserved identifiers, counts, assignments, archive state, forced-RLS inventory, and audit immutability.
- `make test-stabilization` runs the new performance and migration fixtures together with the authenticated permission inventory, custom-role/collection/assigned-only policy suites, recycle recovery, audit immutability, comprehensive IDOR matrix, and raw non-owner runtime-role RLS tests. It is part of `make release-gate`.
- Unsupported nested organization URLs now return to the same authorized organization's overview rather than silently changing to the MSP context. Existing safe workspace-unavailable behavior remains non-disclosing.
- Workspace tests now assert Escape focus restoration. The browser suite adds a keyboard-only workspace-switch journey and axe checks for workspace-unavailable and capability-denied states.
- The performance baseline, migration runbook, architecture, threat model, security baseline, release checklist, engineering risks, OpenAPI contract, version metadata, and roadmap now describe the same `0.1.15` boundary.

The frontend stabilization followed the existing TekDocs design system and introduced no new visual language or copied interface assets.

## Performance evidence

The reference run used Docker Desktop 29.2.1 on an Apple M4 Max host with 12 Docker CPUs and approximately 8 GB assigned memory. Observed API p95 values were:

| Path | p95 | Service queries / budget |
| --- | ---: | ---: |
| Workspace discovery | 7.0 ms | 3 / 12 |
| Organization list | 14.1 ms | 3 / 12 |
| Client People search/list | 15.3 ms | 2 / 4 |
| Client Sites list | 35.7 ms | 2 / 3 |
| Client Entity search | 11.4 ms | 3 / 5 |
| Client relationship discovery | 10.9 ms | 2 / 6 |

These are local regression measurements, not a production sizing claim. Documentation revisions, assets, concurrency, search indexing, and the full 1.0 reference dataset remain future performance obligations recorded in `docs/PERFORMANCE_BASELINE.md` and `TD-RISK-017`.

## Known boundaries

- The reference performance fixture is intentionally limited to implemented domain families. It does not model block revision history, assets, secrets, integrations, or concurrent hosted workloads.
- The migration cycle exercises the latest reversible isolation migration, while the separate rehearsal verifies the oldest supported `0.1.3` upgrade. It is not a promise that arbitrary downgrade paths are supported.
- The development HTTP profile continues to report Django's expected SSL-redirect warning; production settings validate secure public origins and cookies separately.
- The generated OpenAPI schema retains two known enum-name warnings without schema errors. Their stable generated output is checked; cleanup can occur without changing the authorization boundary.
- User-owned editor/example work remains intentionally outside this slice and was not included in its commit.
- No push, tag, deployment, hosted automation, or external publication was performed.
