# TekDocs 0.6.1 public API conventions

Date: 2026-08-12

Status: **local slice complete.** No push, tag, image publication, deployment, hosted workflow, or external security review is implied.

## Delivered boundary

- `/api/v1/` now describes the API version, bounded offset and seek envelopes, strict declared-filter behavior, common error fields, and the limited idempotency contract.
- Shared strict query and offset-page serializers establish reusable server conventions. Existing bounded network collections now reject undocumented filters rather than ignoring them.
- Framework-generated API failures use one correlated error envelope while retaining the old `detail` member temporarily for compatibility.
- Every response receives `X-Request-ID`; bounded valid `Idempotency-Key` values are echoed, but OpenAPI advertises the header only on naturally convergent staff assignment create/delete operations.
- OpenAPI now carries common response headers/errors. `openapi-typescript` generates a checked-in immutable TypeScript path contract, and `openapi-fetch` provides a typed same-origin session/CSRF wrapper plus a validated idempotency helper.

No model or migration was added.

## Risk disposition

- `TD-RISK-012`: **resolved as a reusable convention.** Strict declared filters and bounded pages are now common API primitives; later endpoints must adopt them as they expose collection filters.
- `TD-RISK-044`: **mitigated with remaining owner.** Schema and generated-client drift fail the gate, but 30 inherited list/detail operation-ID collisions still receive generated ordinal suffixes. Explicit stable operation IDs are required in `0.6.9` before `0.7.0` certification.
- `TD-RISK-045`: **mitigated with remaining owner.** The retry header is advertised only for naturally convergent operations. Durable scoped key/fingerprint/result replay for generic integration work remains `0.6.5` and must pass abuse/concurrency stabilization.
