# 0.9.8 candidate — security and Git-backed acceptance

Status: candidate prepared for final validation, not a completed release.
Version metadata identifies this work as 0.9.8; it does not imply a release tag,
successful hosted validation, production deployment, or completed human review.

## Changes

- Harden browser/session versus API-token boundaries, privileged recent-session
  checks, and OIDC public-HTTPS egress with bounded, pinned transport.
- Keep database and transport diagnostics out of public document, inventory,
  invoice, integration and network errors while preserving safe domain feedback.
- Reject malformed import containers and surplus CSV cells instead of silently
  discarding data. Preserve valid quoted fields and optional empty cells.
- Fail retained-file verification on unreadable bytes, including zero-length
  descriptors. Validate secret/media archives before destructive recovery and
  bind restore operations to the explicitly confirmed Compose project.
- Preserve authored Markdown whitespace, correct primary-file section rendering,
  and exercise real-Git editing, layout, conflict and performance behavior.
- Add focused security regression gates, recovery tests, provider checks and
  compatibility-export checks; retain the sharded full-backend release boundary.
- Reconcile the local Wiki draft and validate supplemental setup-guide links
  without weakening the required contextual-help inventory.

No database migration or new runtime dependency is introduced by this candidate.
The separate Wiki checkout remains unpublished and the in-app publication flag
remains disabled. Do not interpret this checkpoint as activating document
authority handoff on an installation.

## Verification and limitations

Local worktree evidence includes 758 frontend tests, 59 script tests, backend
lint/types, migration and API drift checks, production Compose validation, and
the focused security regressions recorded in the
[security review](phase-8-security-review.md).
The [closeout checklist](security-closeout-checklist.md)
records the baseline scan dispositions and exact scope/limitations of each pass.
These results precede the final candidate commit and are not hosted evidence for
that commit. A successful scan job does not itself disposition its findings.

Candidate preparation additionally reran frontend API/lint/types/build and
bundle budgets in Docker with version 0.9.8, plus the remaining local readiness
checks and full local Wiki validator. All pass. The 758 component tests were
not repeated for the metadata-only version change; their preceding worktree
result remains recorded separately. Four existing schema operation-ID collision
warnings remain; schema generation reports no errors or drift.

The staged candidate secret scan reports no leaks. A broader directory scan
reported nine non-credential matches: existing permission route identifiers,
a UI preference key, prose, two test-diff checksums, and an ignored stale build
copy. Checksum labels were clarified without changing their values; no scanner
suppression was added. The unrelated `.ecc/` artifact is excluded from the
candidate. Hosted history scanning and other final security checks remain due.
