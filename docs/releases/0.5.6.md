# TekDocs 0.5.6 retryable SMTP notifications

Date: 2026-08-11

Status: **applicable local slice complete after the listed gates pass.** No push, tag, published image, deployment, hosted workflow, or external security review was performed.

## Delivered boundary

- New permission-filtered inbox notifications create a separate idempotent SMTP queue without retaining destinations or message content.
- Send-time membership, source, topic, organization, surface, and preference checks suppress stale authority.
- Fixed generic multipart templates are autoescaped and contain no authored HTML, document content, publication reasons, credentials, or arbitrary links.
- Temporary SMTP failures retry with bounded backoff and safe status codes; synchronous permanent recipient rejection dead-letters.
- MSP and portal surfaces provide independent CSRF-protected controls for all email, invitation events, and publication events.
- PostgreSQL guards delivery identity/state, preference identity/deletion, membership scope, and forced tenant RLS.

## Compatibility and limitations

Historical `0.5.5` inbox rows are retained but not backfilled into email. New notifications queue normally after upgrade. SMTP remains at-least-once across the narrow crash-after-acceptance window; deterministic Message-ID supports correlation. Asynchronous provider bounce ingestion, batching, digests, quiet time, and delivery administration are not included.

- `make test-notification-email` covers rendering, reauthorization, suppression, preferences, retry/recovery, permanent rejection, database guards, permission isolation, RLS, and frontend behavior.
