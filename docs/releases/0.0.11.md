# TekDocs 0.0.11 authentication hardening evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request or scheduled run.

## Delivered scope

- A blocking authentication-abuse target runs the complete accounts suite, including enumeration-safe failures, CSRF denial, invitation and password-recovery lifecycle/replay behavior, session ownership and invalidation, MFA downgrade and recovery controls, value-free auditing, closed public signup, and the OIDC existing-account boundary.
- The added adversarial cases prove equivalent known/unknown login failures, login session-key rotation, logout invalidation, CSRF denial for reset and invitation mutations, closed signup, and safe behavior for an unconfigured OIDC provider.
- The abuse suite exposed an unconfigured OIDC error path that lacked allauth's required frontend redirect and returned 500. TekDocs now routes that failure to its local sign-in surface without account creation or attacker-controlled redirection.
- Browser automation now runs Chromium on pull requests and Chromium, Firefox, and WebKit on scheduled or manual workflows. Failure artifacts are retained per engine.
- `docs/OPERATOR_AUTHENTICATION.md` documents bootstrap, invitations, password/session incidents, MFA recovery limits, OIDC rollout/rollback, deployment-key handling, validation commands, and escalation boundaries.
- `make upgrade-rehearsal` exports the final supported `0.0.10` source, creates an isolated Compose/PostgreSQL installation with representative owner, membership, password, verified-email, encrypted-TOTP, and append-only audit data, applies `0.0.11`, verifies those invariants, and removes only its temporary resources.
- Version metadata, health responses, OpenAPI, frontend package metadata, overview copy, roadmap, and release evidence agree at `0.0.11`.

## Verification

- `make check` passed Ruff, mypy, migration drift, OpenAPI drift, frontend lint and type checks, all 46 frontend unit/component tests, coverage thresholds, and the production build using the required Node.js 24 runtime.
- `make test` passed 103 backend tests with three intentionally PostgreSQL-only concurrency cases skipped by the fast SQLite settings, plus all 46 frontend tests. Backend coverage was 92.49%; frontend statements were 84.88%.
- `make test-auth-abuse` collected 52 account tests: 49 passed under fast settings and the same three PostgreSQL concurrency cases were skipped.
- `make test-compose` returned ready status at version `0.0.11`, verified Mailpit/SMTP delivery and deployment checks, and passed all 106 backend tests against PostgreSQL with 95.04% coverage.
- `make test-e2e-all` passed all 48 journeys: 16 each in Chromium, Firefox, and WebKit. The suite covers bootstrap, invitation activation/unavailable state, password reset and invalid keys, MFA challenge/enrollment, profile update, safe OIDC presentation, session revocation, responsive navigation, Markdown editing, sign-in accessibility, and sign-out.
- `make upgrade-rehearsal` passed `0.0.10 → 0.0.11`; it preserved and decrypted the encrypted MFA fixture with the original deployment key, preserved the password hash and identity relationships, retained audit records, found no migration drift, and left no rehearsal containers or volumes.
- `make security` found no known Python or production npm vulnerabilities, no Bandit findings, no Gitleaks findings, and no High/Critical vulnerabilities in the backend, frontend, or pinned Mailpit images.

## Boundaries carried forward

- The three-engine workflow changes are locally equivalent but remain inferred for hosted GitHub execution until the repository runs a pull request and scheduled/manual workflow.
- A live external identity provider was not available. Operators must exercise the configured provider through the final HTTPS reverse proxy before production rollout.
- There is deliberately no administrative MFA bypass in this release. Losing the sole owner's authenticator and all recovery codes requires a reviewed recovery or known-good backup rather than an unaudited database edit.
- `0.1.0` is a separate stabilization slice. It adds no new identity feature family and will freeze the current contract only after remaining release blockers, clean-install evidence, and upgrade behavior are certified.
