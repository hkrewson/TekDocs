# TekDocs 0.0.8 session security evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows remain pending publication.

## Delivered scope

- Profile → Settings now opens a responsive Active sessions view with current-browser identification, activity timestamps, refresh, error recovery, and revocation of another browser.
- Session storage, activity updates, user-scoped selection, and underlying Django-session termination use maintained `django-allauth` user-session primitives.
- Authentication success, failure, logout, password reset, client changes, and explicit revocation produce value-free append-only audit records.
- Login and password-recovery rate policies are explicit and use Valkey-backed Django caching consistently across Gunicorn workers.
- The browser gives a specific wait-and-retry message for HTTP 429 without exposing account existence.

## Verification

- `make check`: passed Ruff, mypy, migration drift, OpenAPI drift, frontend lint/type checks, all 37 frontend unit/component tests, and the production build.
- `make test`: passed 73 backend tests with three PostgreSQL-only concurrency skips and 91.21% aggregate coverage; the final frontend suite passes all 37 tests with 86.96% statement coverage.
- `make test-compose`: applied allauth’s `usersessions.0001_initial` migration to the existing PostgreSQL installation, returned ready status at version `0.0.8`, verified SMTP delivery, passed deployment checks with the documented local HTTP exception, and passed all 76 backend tests with 94.57% aggregate coverage.
- A production-settings runtime probe wrote, read, and removed an isolated Django cache key through the configured Valkey cache.
- Session and audit tests cover user-scoped listing, cross-user ID rejection, CSRF denial, remote-session termination, current-session preservation, client-change detection, login success/failure, logout, password reset, and value-free event metadata.
- Rate-limit tests cover HTTP 429 responses for login and password-reset requests; a settings contract test fixes every login, failed-login, request, and reset-completion policy value.
- `make test-e2e`: passed 12 Chromium workflows. The Active sessions workflow covers profile-menu discovery, accessible inventory, and revocation; it also prompted remediation of contrast and landmark issues in the shared shell.
- `make security`: passed `pip-audit`, Bandit with zero findings, npm production audit, Gitleaks with no leaks, and High/Critical Trivy scans for the backend, frontend, and pinned Mailpit image with zero findings.
- OpenAPI generation and drift validation passed at version `0.0.8`; the maintained allauth headless interface remains outside the TekDocs `/api/v1` schema by design.

## Boundaries carried forward

- TOTP, recovery codes, recent reauthentication, privileged-role MFA enforcement, and secret-safe recovery flows remain `0.0.9`.
- Broader profile administration and OIDC provider configuration remain `0.0.10`.
- The allauth headless session interfaces remain outside the TekDocs `/api/v1` OpenAPI schema by design.
