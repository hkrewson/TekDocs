# TekDocs 0.4.8 network stabilization evidence

Date: 2026-08-11

Status: **implementation and applicable local evidence complete.** No push, tag, image publication, deployment, live NetBox access, or other external change was performed.

## Outcome

`0.4.8` adds exact-Workspace cross-family network search and deterministic streamed CSV export, then stabilizes the network subsystem under scale, isolation, upgrade, restore, frontend, and browser gates. It adds no network data model and no import or live connector.

## Security boundary

- Both routes resolve one explicit MSP or organization Workspace and require central `networks.view` authorization before filtering.
- MSP results contain only MSP-owned records; organization results cannot include siblings.
- `tekdocs.networks.v1` is a fixed export schema. It excludes credentials, cost/contract data, hardware-only asset fields, provider payloads, and NetBox observation fingerprints, and escapes spreadsheet formulas.
- Responses are private/non-cacheable and export is streamed in bounded batches.
- The CSV iterator binds its own transaction-local PostgreSQL RLS scope. This is required because response iteration occurs after request middleware closes its transaction, and prevents production runtime roles from returning an empty or incorrectly scoped stream.

## Operator and UI behavior

- The Network page includes “All records,” a Workspace-wide search result table, stable pagination, loading/error/empty states, and routing back to the owning section.
- “Export CSV” downloads the server-generated authorized snapshot. The browser does not reconstruct or broaden the dataset.

## Verification

- `make check` passed: version and supply-chain pin contracts, workflow lint, Ruff, mypy across 103 Python source files, migration and OpenAPI drift, 192 frontend tests, production build, and bundle budgets.
- `make test-networks` passed the complete PostgreSQL network-family, NetBox, relationship, permission/IDOR, forced-RLS, and migration suite.
- `make test-network-stabilization` passed with 100 client Workspaces and 10,000 network Entities, fixed query ceilings, stable pagination, exact-scope export, and local p95 below 500 ms.
- `make network-upgrade-rehearsal` passed from the exact `0.4.7` production image and `make network-backup-rehearsal` passed with separate source/restore projects and fresh database/media volumes.
- `make test-e2e-live` passed in an isolated production-shaped Compose stack. Chromium created real network records, found an exact-Workspace IP through Django/PostgreSQL, and downloaded it through the authenticated streamed CSV route.

The live browser gate initially exposed that Django consumed the CSV iterator after request middleware had closed its transaction-local RLS scope. The export returned only a header under the production runtime database role. The iterator now binds its own exact-Workspace RLS transaction; the focused PostgreSQL test and repeated live journey pass with the expected row. This was a substantive production-path defect found and resolved before closeout.
