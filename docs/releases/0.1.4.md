# TekDocs 0.1.4 workspace switcher evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- The sidebar workspace control now searches the authorized organization directory without loading it wholesale. The MSP workspace remains available regardless of the current query.
- Search input is validated and bounded server-side, results are tenant scoped, archived records are excluded, stable ordering and pagination are explicit, and selector responses contain only the metadata needed for navigation.
- Client, vendor, manufacturer, and partner classifications combine into one workspace capability set. Navigation only offers areas represented by that set.
- Organization selection is carried by the URL. Direct links, refresh, browser history, and separate tabs resolve independently and do not treat browser storage as authority.
- Moving between organization areas preserves the workspace. Returning to the MSP preserves an equivalent top-level area when one exists and otherwise returns to overview.
- Workspace changes abort superseded searches and context loads, ignore late responses, and withhold prior-workspace content while the new authorization result is pending.
- The switcher supports keyboard entry, Arrow Down, Escape with focus restoration, mobile navigation, empty/loading/error states, incremental results, and accessible names.
- Browser automation now runs in a production-built frontend container against Chromium on pull requests and all three Playwright engines through an isolated Compose gate.
- The real-stack organization journey now covers selecting the PostgreSQL-backed organization through the search API, returning to MSP scope, and selecting it again.
- A follow-up navigation refinement makes every visible sidebar route derive from the active workspace, reserves the documented client/MSP domain families without claiming implementation, limits client-context discovery to client-classified organizations, and presents MSP return as a distinct parent-context action.

## Known boundaries

- Organization administration and workspace access remain owner-plus-MFA only until the central policy catalog and scoped RBAC releases. The selector does not create new authority.
- The `0.1.4` domain links establish routes and scope; people, sites, custom fields, relationships, documentation, assets, products, networks, and credentials retain their scheduled implementation slices.
- PostgreSQL RLS remains designed but inactive until `0.1.12`; scoped managers, policy checks, and database integrity guards are defense layers, not a substitute for that milestone.
- The editor bundle warning, user-owned uncommitted editor/example work, reproducible supply-chain inputs, hosted CI proof, database-enforced audit immutability, backups, secret-file enforcement, and structured logging remain tracked in the engineering risk register.
