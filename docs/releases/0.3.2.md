## Known boundaries

- Docker's service-scoped `/run/secrets` mounts are commonly root-owned and mode `0444`; group/other readability is accepted only inside that container-specific mount. Files outside it must be private to root/application ownership and mode.
- Root on the host, container-engine administrators, and root inside the container trust boundary can access mounted runtime material. Secret files reduce ambient process/environment exposure; they do not protect a fully compromised privileged host.
- Process-start keys are not hot-reloaded. Database credentials, Django signing, MFA wrapping, and publication signing require their documented continuity procedure rather than blind file replacement.
- Direct sensitive environment values remain supported for development and migration compatibility until production enforcement in `0.8.7`.
- The 1Password recipe is documentation for an operator action; it was not executed because no vault authority was requested or granted.
