# TekDocs 0.0.9 two-factor authentication evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows remain pending publication.

## Delivered scope

- Settings → Security now supports TOTP enrollment, one-time recovery-code display, remaining-code status, password-confirmed replacement, and password-confirmed disablement.
- TOTP enrollment renders its setup URI as a locally generated QR code while retaining manual key and setup-address fallbacks; enrollment material is not sent to an external QR service.
- Password sign-in recognizes allauth’s pending MFA stage and accepts either a current authenticator value or one unused recovery code before opening the application shell.
- TekDocs implements allauth’s documented MFA encryption adapter hooks with the existing envelope cipher and a deployment-supplied master key. A forward migration encrypts any pre-existing TOTP, recovery seed, or migrated recovery-code material.
- Installation-owner administrative policy requires active TOTP enrollment. The workspace remains available to an owner without TOTP so enrollment and recovery are possible.
- MFA configuration, reauthentication, success, failure, and recovery replacement emit value-free audit events and controlled multipart security notifications.
- TekDocs API errors now preserve maintained exception codes inside the existing structured error envelope so the browser can distinguish policy requirements without parsing human-readable text.
