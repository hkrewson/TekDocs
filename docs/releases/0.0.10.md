# TekDocs 0.0.10 profile and OIDC evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows and a live identity-provider exercise remain pending publication and provider configuration.

## Delivered scope

- Settings now combines profile, two-factor, recovery-code, and active-session administration. Installation members can update their own display name while their verified email remains read-only, and the shell identity updates immediately after a successful save.
- Profile updates require an authenticated installation membership and CSRF-protected session, validate input server-side, and emit a value-free `auth.profile_updated` audit event.
- One environment-configured OpenID Connect provider can be exposed on the sign-in boundary. Public provider discovery returns only its stable identifier and display name; client credentials and discovery configuration remain server-side.
- TekDocs delegates the OpenID Connect authorization redirect, state, callback, token exchange, and issuer/audience/signature validation to maintained allauth social-account components. Automatic signup remains denied, so only an existing invited account with a provider-verified matching email can connect.
- Production validation requires secure redirect, secure session and CSRF cookies, adequate HSTS, an HTTPS public URL, and matching trusted CSRF origins. A deliberately named localhost-only override preserves the HTTP development Compose workflow.
- Version metadata, OpenAPI, environment examples, authentication/security documentation, and the Compose configuration agree at `0.0.10`.

## Boundaries carried forward

- A live external identity provider was not available in the local gate. The discovery and authorization boundary is integration-tested with controlled provider metadata; a configured-provider operator rehearsal remains required before production use.
- The initial boundary supports one OpenID Connect provider and existing-account linking only. Just-in-time public account creation remains closed.
- Authentication abuse-suite expansion, Firefox/WebKit remediation, operator runbooks, and the full upgrade rehearsal remain `0.0.11`.
- Passkeys, SAML, and LDAP/AD-specific integrations remain future work through maintained authentication boundaries.
