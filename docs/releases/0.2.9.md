# TekDocs 0.2.9 documentation-alpha stabilization evidence

Date: 2026-08-09

Status: **implementation complete; certification evidence is recorded below.** No push, tag, deployment, Wiki publication, or other external change was performed.

## Delivered scope

- Replaced the silent 200-revision history ceiling with validated 50-row pagination, a 100-row maximum, complete authorized counts, accessible older/newer navigation, and keyboard-readable diffs.
- Added a 2,500-revision PostgreSQL history fixture to the existing 100-organization/10,000-entity performance gate with query and p95 latency ceilings.
- Kept the editor route-lazy, moved editor CSS and optional syntax assets out of the initial shell, and made 500 KiB shell / 1,200 KiB editor minified budgets executable build failures.
- Added browser accessibility coverage for revision history and a blocking Markdown-help contract test aligned with ADR 0019 and the round-trip/sanitization corpus.
- Added isolated prior-alpha upgrade and database-plus-media backup/restore rehearsals that verify immutable history, attachment bytes, signed STATIC manifests, and retained PDFs.

## Risk disposition

- `TD-RISK-013` is **mitigated with remaining owner**: lazy boundaries and budgets are enforced; representative-device and full-load remediation remains `0.8.5`.
- `TD-RISK-017` is **mitigated with remaining owner**: large-history regression evidence exists at 2,500 revisions; the 250,000-revision/concurrency target remains `0.8.5`/`0.9.4`.
- `TD-RISK-019` is **mitigated with remaining owner**: local executable help drift is blocked; actual GitHub Wiki publication/contextual links remain `0.8.8` and require publication authorization.
- `TD-RISK-006` is **not resolved by this slice**: the disposable restore rehearsal proves scope and dependencies, while supported encrypted backup/key-loss tooling remains `0.8.1`/`0.9.3`.

## Known boundaries

- The editor is still a large optional chunk. The budget prevents regression; it does not claim ideal low-powered-device performance.
- History uses offset pagination. Immutable append-only ordering makes it stable for the current alpha, but cursor pagination may be revisited with the full capacity/concurrency dataset.
- The backup script creates and destroys only uniquely named disposable Compose projects. It does not encrypt, schedule, upload, prune, or operate on a user's normal TekDocs volumes.
