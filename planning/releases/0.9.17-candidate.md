# 0.9.17 candidate: retained document migration checkpoint

Prepared October 31, 2026 on main after published `v0.9.16` (`0ebb981`).
The maintainer authorized this consolidation checkpoint after the completed
monitored-source slice. Preparation baseline: `6cdc4dce85992ece41b7775cc6293c846f4c8c7d`.
Production deployment, live-data migration and Wiki publication remain separate.

## Release notes

- Migrate supported file-backed documents while preserving every primary-file
  version, managed attachment, existing signed publication and retained PDF.
  New Git publications freeze their own retained file evidence.
- Move same-Workspace live shared-block owners and consumers together through
  reviewed atomic groups. Pinned references retain their selected revision;
  rollback preserves supported authored edits and original ownership.
- Migrate approved MSP template sources and enrolled client documents together.
  Preserve copy/live/pinned behavior, local edits and signed history through
  reviewed creation, updates, detach, grouped rollback and recovery.
- Support exact-Workspace field keys, typed entity references and nested
  content-key block substitution. Freeze values and substitution provenance in
  signed snapshots without exposing private values in portable Git metadata.
- Preserve Mermaid source revisions and signed graphics/PDF history. Historical
  validity uses retained signed bytes rather than a changed renderer's output.
- Keep monitored-source settings, schedules, applied pointers and observation
  history in SQL workflow custody. Promoted documents offer current-Git review
  and apply; changed settings/content/index state refuse stale writes, and local
  edits require manual integration rather than automatic replacement.
- Expand real browser/server preservation journeys, PostgreSQL test partitions,
  fresh/0.8.46 migration and independent encrypted-recovery cohorts for these
  supported shapes. Original validation failures remain recorded separately
  from passing corrections and unchanged infrastructure retries.

This release packages the already-reviewed migration slices; it adds no new
application behavior, dependency or schema change beyond that accumulated work.
It includes normal Django migrations 0197–0211 since v0.9.16. Upgrading applies
schema migrations; copying/promoting existing documents remains an explicit
reviewed operator action. Existing signatures, publication records, PDFs and
managed-file versions are retained rather than rewritten.

Client-published legacy-document migration, general cross-Workspace reuse,
repeated legacy block occurrences, broader structural changes and final 1.0
acceptance remain outside this checkpoint. Existing repository-native client
delivery is distinct from migrated-document delivery.
