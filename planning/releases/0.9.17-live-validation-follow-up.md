## Diagnostic contract

The observer records only fixed phase/event names, response codes, durations and
four boolean control-presence flags. It reads neither request bodies/headers nor
download filenames, dialog messages, page-error text or document text. Unknown
scenario/milestone/snapshot strings are discarded or normalized. A failed case
emits at most 128 recent events and 32 pending requests, with numeric truncation
counts. Passing/skipped cases stay silent; per-page listeners and buffers are
disposed after each case. Chromium's ordinary request-aborted/download hand-off
is recorded as events, not classified as an application failure.

The independent Standards review found zero actionable findings. Spec review
identified an overbroad new dialog probe: a filters dialog incorrectly produced
`navigationPrompt: true`. A real Chromium DOM replay reproduced that false
positive. The probe now targets only the open maintained unsaved-changes dialog;
filter-only and actual-guard cases passed. Spec re-review reports zero remaining
findings. This correction affects only the new diagnostic field, not an original
assertion or the unknown hosted timeout causes.

Six Node contract checks exercise the public browser-event adapter. The first
check failed before the observer existed, then passed. An intentional raw-URL
emission mutation made the privacy/buffer contract fail; restoring phase labels
passed again. Tests also cover pending PDF evidence, normal download hand-off,
unknown/private labels, silent success/skips, bounded bursts and listener cleanup.
The checks run explicitly before the live browser gate and live outside browser
test discovery. The existing browser matrix still discovers 415 WebKit cases.
