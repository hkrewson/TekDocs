# TekDocs 0.1.11 custom roles and scoped assignments evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- Tenant-owned custom roles have stable UUID identity, normalized names, descriptions, one immutable tenant or organization scope, maintained permission rows, assignment counts, and archival that immediately stops grants without erasing history.
- The central policy service composes the built-in tenant role with active custom-role assignments. Tenant grants apply in already-reachable workspaces; organization grants apply only to one exact organization.
- Organization reachability remains an independent hard condition. A custom role cannot enter an assigned-only client without a separate organization staff assignment, and it cannot expose a sibling or foreign tenant.
- A centralized custom-role ceiling exposes only selected operational permissions. Ownership, membership and access-control administration, secret access, cost visibility, and other security-boundary permissions cannot be delegated through custom roles.
- Permission metadata remains authoritative for MFA regardless of whether a grant comes from a built-in or custom role.
- Owner-plus-MFA and CSRF-protected APIs list, create, update, and archive custom roles and list, add, and remove tenant- or organization-scoped assignments. Guessed foreign identifiers remain non-disclosing and audit events contain no role or assignment values.
- PostgreSQL triggers enforce tenant consistency, role scope, active-role use, the fixed permission ceiling, owner exclusion, assignment uniqueness, and immutable role/assignment ownership even if application services are bypassed.
- The Access Control interface provides permission-grouped role editing, exact-scope assignment, impact confirmation, archive/removal workflows, duplicate prevention, and responsive accessible states using the existing TekDocs design system.
- The blocking `test-policy` gate now includes the complete custom-role suite.

## Known boundaries

- Custom roles are additive grants, not deny rules. Tenant/client isolation, assigned-only reachability, future MSP-private classification, and future sensitive-field rules override grants.
- Custom roles do not grant access-control administration, secret access, cost visibility, owner powers, or client-portal identity.
- Assignment scope is tenant or exact organization. Collection-scoped assignments arrive in `0.1.12`.
- The PostgreSQL custom-permission allowlist is intentionally a migration snapshot. Expanding the Python delegation ceiling requires a reviewed migration and matching negative tests; a runtime catalog change alone cannot broaden database-accepted permissions.
- Role assignments are retained when a role is archived and become inactive immediately. Explicit assignment removal is destructive configuration cleanup accompanied by an append-only value-free audit event.
