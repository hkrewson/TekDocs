# TekDocs 0.0.3 browser authentication evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows remain pending publication.

## Delivered scope

- The React boundary derives bootstrap, anonymous, and authenticated states from server responses and withholds the application shell until authenticated context succeeds.
- First-owner setup submits the deployment credential only in `X-TekDocs-Bootstrap-Token`, clears credential fields when submission starts, and signs the new owner in through the normal allauth password flow.
- Login and logout use maintained `django-allauth` headless browser endpoints, same-origin session cookies, and Django CSRF validation.
- `GET /api/v1/auth/context` returns the actual authenticated owner and installation tenant. Anonymous and unrelated authenticated identities are denied.
- Bootstrap records the deployment-asserted first-owner address as the verified primary allauth email. This narrow exception is documented and does not apply to future invited users.
- The responsive shell displays the real workspace and owner identity and retains the session with a visible error when logout fails.
- Automated axe scans cover first-owner setup and sign-in; their initial run found and drove correction of insufficient primary-button contrast.

## Verification

- `make check`: passed Ruff, mypy, migration drift, frontend lint/type checks, 23 frontend unit/component tests with 85.53% statement coverage, and the production build.
- `make test`: passed 22 backend fast tests with one PostgreSQL-only concurrency skip and 88.30% aggregate coverage, plus all 23 frontend tests.
- `make test-compose`: built the production-shaped stack, returned ready status at version `0.0.3`, and passed all 23 backend tests against PostgreSQL with 91.70% aggregate coverage.
- `make test-e2e`: passed six Chromium workflows covering authenticated navigation, canonical Markdown editing, mobile navigation, bootstrap, sign-in accessibility, and logout.
- Authentication integration tests proved that missing CSRF rejects login and logout, invalid credentials do not create a session, logout revokes the context, and a non-owner authenticated user cannot enter the shell.
- `make security`: passed `pip-audit`, Bandit with zero findings, npm production audit, Gitleaks with no leaks, and High/Critical Trivy scans for both images with zero findings.
- OpenAPI generation and validation passed with the authenticated-context contract and version `0.0.3`.

## Boundaries carried forward

- Public registration remains closed. Invitations, normal-user email verification, password reset, and development mail capture form `0.0.4`.
- Session inventory/revocation, authentication audit events, and expanded throttling remain `0.0.5`.
- TOTP, recovery codes, recent reauthentication, and privileged-role MFA enforcement remain `0.0.6`.
- The authenticated context deliberately recognizes only the installation owner until scoped roles and controlled identities exist.
- Browser tests mock authentication responses so they do not mutate the development installation; Django integration tests exercise the real allauth and CSRF lifecycle.
