### Stale-browser recovery follow-up

The reported old Integrations chunk returned 404 after an update, while the
current entry named a different chunk that returned 200. Refresh resolved it.
A production-bundle browser regression reproduces an old open tab requesting
a removed module before changing application code. The root router previously
fell through to its framework error screen.

The router now provides a localized, focused recovery screen for dynamic-import
failures, with separate generic guidance for other errors and no displayed raw
diagnostics. It warns that an interrupted draft cannot be recovered here and
requires an explicit unsaved-change acknowledgment before reloading the same
URL. It does not automatically refresh, clear storage, reset sessions, or claim
every failed download means an update. Existing navigation guards remain intact.

This handles lazy modules after the application has started. It cannot recover
a failure to load the initial entry script itself or retain old deployment files.
It is not a draft-persistence implementation. The first test's same-URL failed
module cache did not model a deployment correctly in WebKit; the regression now
versions the whole old module graph and loads current URLs after reload.

Local evidence: 766 frontend component tests, lint, typechecked production
build and bundle budgets pass in Docker. The production-asset browser regression
fails against unchanged `74e62db` and passes against the fix on Chromium,
Firefox and WebKit. Keyboard, narrow-layout and automated accessibility checks
are included in that regression. Hosted workflows must run on the committed fix.
No backend, schema, permissions or dependencies changed in this slice.

## Changes

- Harden browser/session versus API-token boundaries, privileged recent-session
  checks, and OIDC public-HTTPS egress with bounded, pinned transport.
- Keep database and transport diagnostics out of public document, inventory,
  invoice, integration and network errors while preserving safe domain feedback.
- Reject malformed import containers and surplus CSV cells instead of silently
  discarding data. Preserve valid quoted fields and optional empty cells.
- Fail retained-file verification on unreadable bytes, including zero-length
  descriptors. Validate secret/media archives before destructive recovery and
  bind restore operations to the explicitly confirmed Compose project.
- Preserve authored Markdown whitespace, correct primary-file section rendering,
  and exercise real-Git editing, layout, conflict and performance behavior.
- Add focused security regression gates, recovery tests, provider checks and
  compatibility-export checks; retain the sharded full-backend release boundary.
- Reconcile the local Wiki draft and validate supplemental setup-guide links
  without weakening the required contextual-help inventory.

No new database migration or runtime dependency is introduced by this candidate.
The historical owner-backfill migration is repaired as described below.
The separate Wiki checkout remains unpublished and the in-app publication flag
remains disabled. Do not interpret this checkpoint as activating document
authority handoff on an installation.
