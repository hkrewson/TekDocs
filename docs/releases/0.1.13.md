# TekDocs 0.1.13 recovery and authorization certification evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- MSP and organization workspaces now expose a bounded recycle bin for archived organizations, person associations, sites, location subtrees, and custom-field definitions. Search and type filters are bounded, and each result carries only its stable type, identifier, display label, archive time, and cascade count.
- Recovery is a separate central-policy action. It requires `recycle_bin.restore`, the domain's existing archive or management permission, recent MFA, exact workspace reachability, and CSRF. Archived organizations are recoverable only from the MSP workspace.
- Site and location recovery uses the archive timestamp as a cascade identity. It restores only descendants archived by the same operation, preserves older independent archives, validates retained dependencies, and fails atomically on conflicts.
- PostgreSQL now makes audit rows insert-only with a `BEFORE UPDATE OR DELETE` trigger. ORM instance operations, queryset updates, raw SQL, and cascades cannot alter or remove an audit row through the application database path.
- A maintained inventory enumerates every authenticated API route, supported method, permission, scope, MFA requirement, and CSRF expectation. The blocking matrix proves inventory completeness and exercises anonymous, non-member, insufficient-role, malformed or guessed identifier, missing-MFA, and CSRF denial; domain suites retain semantic cross-tenant, sibling-client, and assigned-only checks.
- Authorization is evaluated before mutation-payload validation on access-control endpoints, closing a validation-oracle path discovered by the generalized matrix.
- The application shell adds a restrained Governance recycle-bin route in both MSP and organization context, with keyboard-accessible filters, confirmation, cascade impact, loading, empty, denial, conflict, stale-workspace, and recovery states.
- OpenAPI, architecture, information architecture, threat model, security guidance, engineering risks, ADR 0016, and the roadmap now describe the same implemented boundary.

## Assigned risk disposition

- `TD-RISK-001` — **current route families certified.** The central policy composition is now backed by a complete maintained route inventory plus generalized denial and domain-semantic isolation suites. Every future API family must enter the inventory and add domain-specific cases before exposure; full entity/RBAC subsystem stabilization remains `0.2.0`.
- `TD-RISK-002` — **still open.** Structural PostgreSQL guards remain active, but a non-owner runtime role with active RLS is scheduled for `0.1.14` and remains a prerequisite for full isolation certification.
- `TD-RISK-008` — **resolved for supported row mutations.** PostgreSQL rejects audit-row updates and deletes below the ORM. Destructive table/schema administration remains explicitly inside the trusted database-owner boundary.
- `TD-RISK-009` and `TD-RISK-010` — **still open.** Reproducible runtime inputs and hosted workflow evidence remain assigned to `0.1.14`.

## Known boundaries

- The recycle bin is a deliberate recovery workflow for the five listed archival record families, not a generic undelete facility. Authentication records, access-control configuration, relationship edges, audit events, and future STATIC publications are excluded.
- Restoring a parent does not revive a child archived in an older independent operation. Missing or archived external dependencies require an operator to restore the dependency first.
- The audit trigger blocks row updates and deletes by the application database path. A trusted database owner can still perform destructive schema/table administration, including dropping the trigger or table; TekDocs exposes no application bypass.
- The route inventory proves that implemented authenticated routes are cataloged and subjected to common negative cases. It complements rather than replaces each domain's semantic authorization tests.
- Active runtime-role RLS, reproducible Python inputs, and hosted GitHub automation evidence remain the next slice rather than being claimed by this release.
