# TekDocs 0.0.4 email foundation evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows remain pending publication.

## Delivered scope

- The default Compose stack captures development mail in a persistent Mailpit service whose browser UI is exposed only on host loopback and whose SMTP port remains internal.
- TekDocs-authored transactional mail crosses one Django service boundary that renders canonical text and HTML templates and rejects malformed recipients and injected headers.
- Production configuration validation rejects non-SMTP delivery, absent or malformed connection values, partial credentials, conflicting encryption modes, invalid senders, and plaintext SMTP without an explicit deployment acknowledgement.
- `make mail-test EMAIL_TO=address` gives operators a real SMTP delivery probe without echoing the recipient, credentials, subject, or message contents.
- Local and hosted security workflows scan the exact Mailpit image digest alongside the TekDocs application images.
- OpenAPI drift checking now compares freshly generated output with the committed contract instead of rewriting the committed file before comparison.

## Verification

- `make check`: passed Ruff, mypy, migration drift, OpenAPI drift, frontend lint/type checks, 23 frontend unit/component tests with 85.53% statement coverage, and the production build.
- `make test`: passed 39 backend tests with one PostgreSQL-only concurrency skip and 89.72% aggregate coverage, plus all 23 frontend tests.
- `make test-compose`: built the production-shaped stack, returned ready status at version `0.0.4`, confirmed Mailpit readiness, delivered a multipart test message through SMTP, and passed all 40 backend tests against PostgreSQL with 92.75% aggregate coverage.
- `make test-e2e`: passed six Chromium workflows, including automated axe checks.
- Email tests cover multipart rendering, recipient and subject injection, safe operator success/failure output, and production SMTP configuration rejection.
- `make security`: passed `pip-audit`, Bandit with zero findings, npm production audit, Gitleaks with no leaks, and blocking High/Critical Trivy scans for the backend, frontend, and pinned Mailpit digest with zero findings.
- OpenAPI generation and validation passed at version `0.0.4`.

## Supply-chain decision

Available stable Mailpit images contained High-severity dependency findings during verification. TekDocs therefore pins a tested upstream development image by immutable digest rather than silently accepting those findings or following a mutable tag at runtime. The selected digest produced zero High/Critical findings and is limited to the development mail-capture role. It should be replaced by the next clean stable release after verification.

## Boundaries carried forward

- Invitation issuance and delivery remain `0.0.5`; invitation acceptance and verified-email activation remain `0.0.6`.
- Password recovery remains `0.0.7`.
- Mail delivery remains synchronous in this foundation slice. Queues, retries, delivery events, notifications, and bounce handling remain later roadmap work.
- Mailpit is a development aid, not a supported production mail service. Its inbox must not receive customer information, real credentials, or secrets.
