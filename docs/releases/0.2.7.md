# TekDocs 0.2.7 immutable STATIC publication evidence

Date: 2026-08-09

Status: **complete and locally certified.** No push, tag, deployment, Wiki publication, or other external change was performed.

## Delivered scope

- Added a separate append-only `DocumentPublication` record so publishing never freezes or mutates its editable source document.
- Added transactionally locked dependency resolution for ordered live/pinned placements, exact immutable block revisions, authorized entity projections, and active source-owned attachment metadata. Missing, foreign, or archived dependencies fail atomically.
- Added the versioned `tekdocs-static-publication/v1` canonical JSON manifest plus retained canonical Markdown and sanitized HTML. A length-delimited snapshot payload prevents ambiguous byte concatenation.
- Added SHA-256 content digests and Ed25519 signatures using a deployment-supplied private key. Each publication retains its public verification key, key fingerprint, algorithm, signature, and fresh verification result; private key material never enters the database or API.
- Added Django and PostgreSQL append-only enforcement, manifest/workspace identity guards, forced RLS, central-policy/MFA/CSRF route coverage, and non-disclosing sibling/cross-tenant cases.
- Added restrained Documentation-page publication controls, immutable title-list entries, stored-HTML viewing through the existing sanitizer, verification metadata, and private Markdown/manifest downloads.

## Known boundaries

- The Ed25519 signature proves that the deployment key signed the publication digest. It is not a legal electronic signature or an external trusted timestamp.
- This slice signs attachment identity and checksum metadata, not a retained copy of attachment bytes. Deterministic PDF and retained artifact packaging are assigned to `0.2.8`.
- Publication audience, reason, correction, supersession, and retention workflows are assigned to `0.2.8`; existing publications remain immutable and cannot be deleted through the application.
- The signing key is environment-supplied today. `*_FILE` injection, operational key rotation, and an operator-owned secret-manager recipe remain assigned to `TD-RISK-004` and `0.3.2`; retained public keys keep older publications verifiable after future rotation.
