# TekDocs 0.5.7 notification scheduling and delivery administration

Date: 2026-08-11

Status: **applicable local slice complete.** No push, tag, published image, deployment, hosted workflow, or external security review was performed.

## Delivered boundary

- One bounded SMTP digest now carries up to 25 currently authorized notifications for one recipient and surface.
- Immediate, hourly, and daily delivery schedules use explicit IANA time zones; optional quiet hours defer mail and support overnight windows.
- User preferences remain surface-scoped, CSRF-protected, membership-guarded, undeletable, and checked immediately before delivery.
- Owner/administrator delivery administration lists only value-minimized metadata and permits controlled retry only for dead-lettered work.
- Retry requires a reason, increments a generation, creates append-only audit evidence, and is enforced by PostgreSQL transition guards.
- The restrained application surface adds scheduling controls in the existing notification popover and a separate permission-gated email-delivery table.

## Compatibility and limitations

Existing `0.5.6` preferences migrate to immediate delivery in UTC with no quiet window. Existing pending, delivered, suppressed, and dead-letter rows retain their identity and state. SMTP remains at-least-once across the crash-after-acceptance window. Asynchronous bounce ingestion and provider analytics are not claimed.
