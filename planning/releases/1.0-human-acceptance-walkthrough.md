# TekDocs 1.0 human acceptance walkthrough

Status: **not started**. This checklist records the human review that automated
browser and accessibility checks cannot replace. It does not authorize a release,
deployment, production change, Wiki publication, or migration of existing content.

Use synthetic records in a designated acceptance installation. Complete every
profile for both the MSP workspace and one synthetic organization workspace.
Check a box only when the expected result is true. Write **Fail**, **Blocked**, or
**Not run** in the run record when it is not. Never enter credentials, recovery
codes, real client information, or private document contents in this file or in
screenshots.

## 1. Record the run

- [ ] **RUN-01 — Identify the candidate.** Record the exact commit and acceptance
  URL below. A displayed `1.0.0` version is not enough to identify the build.
- [ ] **RUN-02 — Identify the environment.** Record browser, browser version,
  operating system, device, screen reader and account role. Do not record login
  secrets.
- [ ] **RUN-03 — Confirm safe fixtures.** Confirm there is synthetic MSP data,
  Organization A, a second organization with a distinct isolation marker, long
  names, more than 25 records in relevant collections, a Git-backed document,
  a harmless file, a reusable template and ordinary editable test records.
- [ ] **RUN-04 — Confirm safe boundaries.** Email, webhooks and integrations use
  test destinations. The walkthrough must not dispose of a real asset, archive a
  real contract, publish to a real client, or start a live network synchronization.

## 2. Desktop keyboard session

Use a maintained desktop browser at 1280 CSS pixels or wider, then shorten the
window height. Put the pointer aside. Use Tab, Shift+Tab, Enter, Space, arrow keys,
Escape, browser Back and browser Forward.

### Shared keyboard checks

- [ ] **KEY-01 — Enter and leave each workspace.** Visit Assets, Contracts,
  Networks, Documentation and Files in the MSP workspace, then repeat in
  Organization A. Expected: the page heading and current workspace are clear,
  focus is visible, and no action depends on hover.
- [ ] **KEY-02 — Search an off-page record.** In each collection, search for the
  prepared record beyond the first page, change one filter and sort order, open
  the result, then use browser Back. Expected: the full collection is searched;
  the same query, filter, order and useful focus location return.
- [ ] **KEY-03 — Verify dialogs.** Start a harmless edit, attempt to leave, choose
  **Keep editing**, attempt again, then choose **Discard changes**. Expected: the
  warning appears immediately, focus stays inside it, Escape behaves like Keep
  editing, the chosen draft is preserved or discarded, and focus returns to the
  control that opened the destination.
- [ ] **KEY-04 — Verify validation.** Remove a required synthetic value and save.
  Expected: the error identifies the problem, focus or an announcement makes it
  discoverable, other entered values remain, and correcting the value succeeds
  exactly once.
- [ ] **KEY-05 — Verify isolation.** In Organization A, search for the second
  organization's marker and try its prepared direct link with the A-only role.
  Expected: no foreign record, metadata, file preview, search result or download
  is exposed, including briefly during loading.

### Assets

- [ ] **KEY-AST-01 — Inspect a hardware record.** Open Overview, Specifications,
  Network, Related and History, then open the full page and return. Expected: the
  asset identity remains clear and the collection context is restored.
- [ ] **KEY-AST-02 — Exercise an ordinary change.** Change a synthetic custody or
  status value, save and reopen. Expected: the value and useful history persist.
- [ ] **KEY-AST-03 — Cancel a consequential action.** Open the disposal or archive
  confirmation and cancel it. Expected: consequences are described, focus is
  contained and restored, and the asset is unchanged.

### Contracts

- [ ] **KEY-CON-01 — Inspect the record.** Open Overview, Costs, Related and
  History. Expected: every amount retains its currency and billing interval and
  long values remain associated with their labels.
- [ ] **KEY-CON-02 — Check restricted costs.** Repeat with a role lacking cost
  permission. Expected: financial values and actions are absent and a useful
  explanation replaces them.
- [ ] **KEY-CON-03 — Edit without archiving.** Save one harmless change, reopen it,
  then open and cancel the archive confirmation. Expected: the edit persists and
  cancellation leaves the contract active.

### Networks

- [ ] **KEY-NET-01 — Move through network views.** Visit Networks, Devices, DNS,
  Wireless and NetBox, open a record in each applicable view and refresh one
  direct section URL. Expected: the same record and section return.
- [ ] **KEY-NET-02 — Confirm a two-sided assignment.** Assign one prepared unused
  synthetic IP to the test asset, then open the asset. Expected: subnet and asset
  show the same address and workspace.
- [ ] **KEY-NET-03 — Inspect provenance.** Open the prepared imported device and
  DNS record. Expected: asset/model/serial/rack details and provider source are
  understandable, with local data not presented as an upstream change.

### Documentation and Files

- [ ] **KEY-DOC-01 — Edit canonical Markdown.** Add a small heading, checklist and
  fenced code sample to the prepared Git-backed document; save, reload and reopen
  editing. Expected: blank lines and indentation are retained, rendering remains
  readable, and the save has an identifiable Git revision.
- [ ] **KEY-DOC-02 — Review history and a stale edit.** Make a second edit, inspect
  history, then open the same saved revision in two tabs and save different edits.
  Expected: the stale tab cannot silently overwrite the newer revision; its draft
  survives and the recovery choice is understandable.
- [ ] **KEY-DOC-03 — Exercise reusable content.** Create a disposable document from
  the prepared template and review copy/live/pinned behavior where offered.
  Expected: the resulting content and update policy are explicit; no unexpected
  section changes while merely reviewing an update.
- [ ] **KEY-DOC-04 — Round-trip a file.** Search Files for the prepared off-page
  item, open its owning document, download the harmless file, then use browser
  Back. Expected: the download matches the fixture and the same Files result,
  query and focus return.
- [ ] **KEY-DOC-05 — Review draft protection.** Change Document settings, activate
  Files, choose Keep editing, activate Files again and choose Discard changes.
  Expected: the warning is immediate, the first choice keeps the exact value, the
  second opens Files, and focus restoration is useful in both cases.
- [ ] **KEY-DOC-06 — Inspect retained publication evidence.** Open the prepared
  retained publication, its PDF/file and history. Expected: retained content is
  clearly distinct from the editable source and does not silently change after a
  harmless source edit.

## 3. Touch and mobile session

Prefer a real phone or tablet. If using emulation, record that limitation. Use a
390 CSS-pixel viewport and spot-check 320 pixels. Open the software keyboard in at
least one editor.

- [ ] **MOB-01 — Navigate all four groups.** Expected: the current workspace and
  page remain clear, every primary action has a usable touch target, and no
  horizontal page scroll is required.
- [ ] **MOB-02 — Open and close one record per group.** Expected: a record uses one
  understandable scrolling surface; the labeled Back action returns to the same
  collection state.
- [ ] **MOB-03 — Edit with the software keyboard.** Edit one harmless field in each
  group and the Markdown body in Documentation. Expected: the active field, error
  and primary save/cancel actions remain reachable when the keyboard is visible.
- [ ] **MOB-04 — Use mobile section navigation.** Visit Asset sections, Contract
  Costs, Network views and Document Files/History. Expected: the section control
  has a useful label and the chosen section is visibly and programmatically clear.
- [ ] **MOB-05 — Protect a draft.** Repeat the Documentation settings-to-Files
  Keep/Discard check. Expected: the dialog fits, scrolls if needed, traps focus for
  keyboard users, and neither action is hidden behind browser or software-keyboard
  chrome.
- [ ] **MOB-06 — Check long content.** Open the prepared long asset identifier,
  contract value, network address/name and filename. Expected: text wraps or an
  intentional local scroller is obvious; essential controls never overlap it.

## 4. Screen-reader session

Preferred macOS pairing: VoiceOver with Safari. Turn VoiceOver on with Command-F5
or Accessibility settings. Use VoiceOver+Right/Left, VoiceOver+Space and the rotor.
Another maintained browser/reader pairing is acceptable when recorded.

- [ ] **SR-01 — Identify page structure.** On each group landing page, inspect the
  page title, main landmark, headings, collection name and workspace. Expected:
  the page can be understood without its visual layout.
- [ ] **SR-02 — Find and open a record.** Search and open one record per group.
  Expected: search, filters, result count, record name, loading state and final
  heading are announced in a useful order.
- [ ] **SR-03 — Navigate sections.** Move among the group-specific sections used in
  the keyboard session. Expected: controls expose name, role, state and current
  selection; icon-only controls have meaningful names.
- [ ] **SR-04 — Hear errors and success.** Trigger the prepared validation error,
  correct it and save. Expected: the error and completion are announced once,
  without moving unexpectedly to another workspace or record.
- [ ] **SR-05 — Hear draft protection.** Repeat Keep editing and Discard changes.
  Expected: the dialog title and description are announced, initial focus is on
  Keep editing, focus cannot escape the open dialog, and closing restores context.
- [ ] **SR-06 — Distinguish document states.** Open an editable document, template
  review, retained publication, PDF/file and unavailable/denied example. Expected:
  draft, live source, retained evidence, loading, empty, error and denied states
  have distinct useful announcements.
- [ ] **SR-07 — Verify Files return.** Search Files, open the owning document and go
  Back. Expected: the returned file result and useful focus location are announced.

## 5. Native 200% zoom session

Use the browser's native zoom control, not CSS zoom or a resized screenshot.
Record the window size and resulting CSS viewport if available. Use the prepared
long values.

- [ ] **ZOM-01 — Review every group landing page at 200%.** Expected: essential
  information is available, reading order still makes sense, and the page does
  not require horizontal scrolling.
- [ ] **ZOM-02 — Open one detailed record per group.** Expected: headings, section
  navigation, primary actions and status messages do not overlap or become clipped.
- [ ] **ZOM-03 — Edit and validate.** Expected: the focused field and its error stay
  visible; sticky headers or footers do not cover them.
- [ ] **ZOM-04 — Open confirmations and draft protection.** Expected: dialogs fit
  the viewport, remain scrollable, expose every action and restore useful focus.
- [ ] **ZOM-05 — Review specialized content.** Inspect long filenames, Markdown/code,
  a PDF/file view and network topology/table where available. Expected: any local
  scrolling region is labeled or understandable and does not force whole-page
  two-dimensional scrolling.

## 7. Final human decision

- [ ] Every required profile/group row has passing MSP and Organization A evidence,
  or an explicitly approved scope decision identifies what remains unverified.
- [ ] Every failure or blocker has a recorded owner and release disposition.
- [ ] The accepted commit agrees with hosted CI and the commit-matched security
  review; a later source change invalidates those exact-source claims.
- [ ] The reviewer completed one realistic synthetic support job spanning an asset,
  its documentation, related network/contract information and Files return without
  an undisclosed workaround.
