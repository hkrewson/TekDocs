## Release notes and reviewed boundaries

- Promoted legacy documents permit owned fragment Markdown edits. Root metadata,
  identity, body, includes, fragment metadata, moves, deletion and duplicate
  protected identities are rejected before accepting a Git commit.
- The guard uses exact tenant, workspace and legacy ownership and shares its
  snapshot comparison with rollback. Native Git documents remain editable.
  Existing caller authorization and RLS remain required; this validator is not
  a replacement permission service.
- The writer runs validation under its Git lock and repository row lock after
  accepted-base/reconciliation checks. Authority transitions now pin Git first,
  matching that lock order. Tests prove deterministic lock exclusion; exhaustive
  concurrent-process behavior is not claimed.
- Supported rollback appends legacy revisions and preserves history. The
  encrypted recovery rehearsal preserves edited content through restore and
  reversal. Previously accepted structural drift is still a rollback blocker.
- Historical upgrade setup now uses the original migration service to seed
  0.8.46 data. It avoids an unused obsolete renderer build without changing the
  fixture, migrations or comparisons. Current backend/renderer startup remains
  required. This does not certify the old HTTP/renderer stack.
- Frontend toolchain alignment and completed-download browser assertions are
  covered by the merged CI follow-up records. Release-status tooling now checks
  required jobs in the single-push run rather than treating green parent runs
  as proof of skipped release work.

No new release-blocking defect was identified in this bounded delta review.
No new end-user authority UI or public migration procedure is introduced. ADR
0115 keeps the first operator migration internal; public updater instructions
remain applicable. Preserve Git ancestry when delivering to main.
