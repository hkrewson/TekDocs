# Post-0.9.17 publication CI lifetime correction

## Slice and acceptance

Fix the real publication browser harness failure in documentation-source
`8195f054`, Build [41325634983](https://github.com/hkrewson/TekDocs/actions/runs/41325634983),
live job `124906932721`. Keep all publication, authorization, retained PDF/file,
rollback and recovery assertions, 120-second per-case deadlines and zero retries.
Keep a finite suite deadline and retain original failure evidence. This is CI
coordination only; application APIs, schema, release identities and production
remain unchanged. The older portal-notification cause remains unknown separately.

## Diagnosis and reproduction

Verified: the server fixture allowed only 240 seconds for the entire serial
browser suite. The failed hosted run finished signed-history assertions before
starting its independent template cohort around 60 seconds. That combined case
expired at 120 seconds with a template request pending for only 2079 ms. Three
other cases passed. The later monitored PDF request returned HTTP 502 in 2 ms
around the server's 240-second shutdown; no download event followed.

Controlled reproduction used the existing `tekdocs` project and publication
controller, with only the browser launch replaced by a public health check and
245-second pause. Before any browser test ran, the health endpoint returned 200;
at elapsed 245165 ms it returned 502. Server verification failed. This establishes
the independent premature-server-shutdown defect. The hosted timing correlation
is inferred; the failed job did not retain an exact server shutdown timestamp.

## Correction

A public shared budget gives Playwright a finite 15-minute suite ceiling, while
retaining 120 seconds per case and zero retries. The server reads that same budget
before announcing readiness, then allows one additional minute for result handoff.
Missing completion still fails, failed completion still fails, and the original
server-side custody/rollback/recovery verification still runs after completion.

Signed history and enrolled templates now run as separate serial browser cases
against their already independent fixture cohorts. The unchanged template helper
gets its own 120-second case, without changing its selectors, requests or checks.
There are six cases. Template diagnostics retain the same value-free contract.

## Validation

Verified corrected controlled replay: health returned 200 initially and after
245175 ms, then all six real browser cases passed in 2.2 minutes, zero retries.
The unchanged server custody/file/PDF/rollback/recovery verification and safe
artifact hygiene passed. Original red and corrected green use the same 245-second
controller pause; all other fixture setup and cleanup remained intact.

Verified checks: six completion-protocol cases, the tooling Make gate (140 tests,
three existing optional skips), 793 frontend cases across 128 files, lint,
typecheck, production build/bundle budgets, backend Ruff and mypy (293 files),
API contract, source-secret scan, version/pin checks and local Wiki links. Both independent
source-review axes reported zero actionable findings. The standard
`make test-publication-browser-live` also passed separately: six cases in 2.0
minutes, zero retries, original server verification and artifact hygiene passed. Local
replays use only existing services and a generated database within the existing
database service. No additional project, service, container or volume is created.
Hosted CI must confirm the full exact-source matrix and production-image gates.

Full `make check` and `make release-gate` are not run unchanged locally: their
Compose-run/fallback/rehearsal paths provision additional containers or isolated
environments prohibited by the local-project instruction. Relevant frontend and
backend checks above were adapted to `docker compose exec` against the existing
services. The exact-source hosted Build owns the full database matrix, workspace
journey, security and production-image checks; hosted validation is pending push.

Wiki updates remain local drafts; no Wiki publication or production action is
authorized by this CI correction. Existing candidate risk decisions are unchanged.
