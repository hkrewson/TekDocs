# TekDocs 0.9.4: Operational entity context and content-graph reads

Date: 2026-10-05. Application version is `0.9.4` after issue #103.

## Completed slice

- Canonical Markdown and frontmatter reference operational entity UUIDs using
  typed relationships or `tekdocs://entity/<uuid>` narrative links.
- The accepted Git commit yields a rebuildable, workspace-scoped entity-link
  projection, including links in included fragments. A migration invalidates
  the prior index marker for deterministic rebuild.
- Staff-only collection, search, health, document-detail and entity-backlink
  APIs resolve permitted context at read time. An asset's Documentation tab
  separates exact-device, model and product-class guidance.
- Incoming links are informational. They cannot include content or grant
  access. Client portal users remain on approved publication routes.

## Validation evidence

- `make test-content-read` passed against PostgreSQL, covering typed and
  narrative references, exact/model/class backlinks, included pinned fragment
  references, dynamic labels, search, health, cross-organization denial,
  forced-RLS isolation and the exact-prior migration rebuild.
- `make check` passed, including the frontend test suite, production frontend
  build, lint/type checks, version alignment, migration drift and OpenAPI
  contract checks. The API contract tests also passed against PostgreSQL.

## Deliberate limits

The existing editor, template enrollment, publications and database-backed
document operations remain unchanged. The new reads use the current workspace
repository only. Managed Git authoring is `0.9.5`; legacy migration is
`0.9.6`; publication and recovery parity are `0.9.7`. No deployment or hosted
validation is claimed by this local checkpoint.
