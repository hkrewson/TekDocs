# 0.9.19 candidate: Git-backed document workflow consolidation

Prepared November 5, 2026 from published v0.9.18
(`81fed48fd2d4810542af43e703f5842589ed0ff4`). Preparation baseline:
`bf764ca24d56c42d7b437ad5dbef9147a402952e`.

This packet freezes the accumulated post-0.9.18 work as the next tested
development checkpoint. The maintainer authorized the v0.9.19 push to `main` and
the single-push pipeline's image, tag and receipt delivery on November 5, 2026.
Production deployment, live-data migration and final 1.0 acceptance remain
separate and are not authorized here.

## Release notes

- Preserve repeated same-Workspace shared-block placements and scoped
  cross-Workspace library reuse, including distinct live/pinned provenance,
  fail-closed ambiguity handling, rollback, and retained publication custody.
- Add complete Git-native document discovery and Markdown export so native-only
  documents appear in the library and cross-checked export inventory.
- Connect new Git documents to internal and client publication workflows,
  corrections, withdrawals, retained PDFs, history, and exact-client portal
  authorization.
- Add managed primary-file version controls, Git-native field/content-key and
  entity-reference configuration, native template enrollment, and monitored
  remote-source configuration with immutable publication evidence.
- Add normal Django migrations 0213 through 0223. Upgrade applies schema only;
  document copying, promotion, and authority handoff remain explicit reviewed
  actions. Existing records and signed artifacts are not rewritten by the
  version change.
- Define CI lanes, scheduled-assurance freshness checks, immutable release
  discovery, and an updater that exits before backup or Docker activity when the
  selected verified release is already deployed.
- Remediate the KaTeX/minimatch/Zod diagram and lint dependency chain, update
  setuptools to 84.2.1, and constrain development-only filelock/msgpack to fixed
  versions. Split the oversized database shard without dropping tests, coverage,
  or final-gate requirements.

This candidate packages reviewed development work. The preparation patch changes
version metadata and release documentation only. The six deferred automatic
legacy-migration shapes, clean-start human acceptance, recurring browser timing
investigation, production deployment, and aggregate 1.0 acceptance remain outside
this checkpoint. Existing data remains intact.

runtime delta from v0.9.18 through the preparation baseline. The bounded slice
specifications, ADRs, development notes, and failure ledger retain their detailed
acceptance criteria, reproductions, negative tests, and unresolved timing limits.

Supporting source `bf764ca2` passed
[Build 42101197293](https://github.com/hkrewson/TekDocs/actions/runs/42101197293)
on attempt 2. All application checks, database shards, combined coverage, browser
acceptance, production-container, SBOM, vulnerability, and stable final-gate jobs

Extended validation, publication, attestation, and receipt jobs were intentionally

The first authorized release attempt, [run 42130193781](https://github.com/hkrewson/TekDocs/actions/runs/42130193781),

0223. The correction freezes the actual 0.8.46 field boundary and adds a focused

The same run also showed that failure triage used the strict operator exit code
after successfully generating its inventory; report-only mode now separates a
readable failed-run report from an inventory error, and run-ID normalization
correctly recognizes the repository's string-valued ledger entries. Both root
failures and the consequential stable-gate rejection remain in the
[failure ledger](validation-failures.json). Exact corrected-source hosted
validation is required before publication.

Local validation reuses the existing `tekdocs` Compose project. Gates that create
additional projects, databases, or volumes remain hosted release requirements.

## Current-candidate risk decision

The v0.9.18 acceptance expired at this next runtime candidate and is not carried
forward. Dependency remediation clears the prior KaTeX-chain and recorded
development/build-tool advisories from this decision. Two unchanged browser-policy
limitations remain:

- Medium: the compatibility CSP retains `style-src 'self' 'unsafe-inline'`.
- Low: Cross-Origin-Embedder-Policy is absent; TekDocs does not claim cross-origin
  isolation.

On November 5, 2026, the maintainer accepted both limitations for **v0.9.19 only**
and explicitly noted that they must be resolved. Review or remediate them before
the next runtime candidate or November 12, 2026, whichever comes first. This is a
bounded release decision, not a permanent waiver. Green CI cannot extend it. Any
new hosted finding must also be assessed before release completion. No
High/Critical runtime exception is proposed, and this checkpoint does not claim
independent human or final 1.0 security acceptance.
