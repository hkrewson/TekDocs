# TekDocs 0.9.3: File-backed reusable fragment composition

Date: 2026-10-05. Application version is `0.9.3` after issue #102.

## Completed slice

- Documents and fragments own ordered `includes` with live or exact-commit
  pinned resolution and explicit audience profiles.
- Independent copies use new fragment IDs and retain optional exact-source
  provenance without following later edits.
- Nested composition has deterministic manifests, audience-specific Markdown,
  where-used backlinks, and cycle, depth, node-count and expanded-byte limits.
- Pinned content and template sources resolve only from retained commits in
  the exact repository. Missing/changed/current template sources have an
  explicit conflict preview and warning finding.
- Invalid accepted composition preserves the last-known-good projection and
  records value-minimized diagnostics. The migration requires reindexing from
  each accepted commit for the new derived fields.
- Forced-RLS rows and database scope triggers constrain include and template
  projections. Client portal users cannot read raw repository content graphs.

## Validation evidence

- Parser tests reject malformed modes, audiences and object IDs.
- PostgreSQL tests cover nested live and pinned expansion, audience variants,
  independent-copy provenance, template changes, rollback by new commit,
  cycle retention, foreign pin rejection and client denial.
- The named composition gate includes the full runtime-role RLS inventory.
- Migration consistency, OpenAPI, generated browser types, lint, type checks,
  version alignment and the composed `make check` gate pass.

## Deliberate limits

The existing database-backed editor, template enrollment workflow and STATIC
publication path are retained. This checkpoint does not migrate old documents,
provide managed Git authoring, expose client repository graph reads, publish a
new image, deploy or claim pilot/security assessment evidence. Issue #103 owns
operational entity context and read paths in `0.9.4`.
