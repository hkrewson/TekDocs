# 0.9.11 security maintenance candidate

Prepared October 21, 2026. Scope: Node October security fixes and a patched
Mailpit rebuild, including the fourth image's delivery contract. No database
migration or API behavior change; version metadata advances to 0.9.11.

## Acceptance criteria

- Node 24.22.1 in renderer, frontend build/development, local gate fallback,
  hosted Node jobs and Playwright tooling; retained browser versions still work.
- Mailpit v1.31.6 rebuilt from verified source with Go 1.27.3, preserving SMTP
  capture and persistent data. No vulnerability exceptions.
- Mailpit is scanned, attested and delivered by immutable digest with the other
  images; older release receipts still work, and missing/mismatched Mailpit
  identity is rejected before stopping services.
- Frontend, production runtime, mail persistence, image scans and deployment
  contracts pass. Exact-commit hosted gates must confirm the committed candidate.

## Evidence and limits

The old pinned Node image metadata identifies 24.19.0. The upstream Node
[October advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)
and [24.22.1 release](https://nodejs.org/en/blog/release/v24.22.1/) identify the fix.
Local Docker confirmed 24.22.1 in the rebuilt renderer and browser test image;
Chromium, Firefox and WebKit each launched and rendered a synthetic page.
Frontend validation passed 127 files / 772 tests, lint, typecheck, OpenAPI check
and production build/bundle budgets on patched Node.

The exact old Mailpit image scan reproduced CVE-2026-111943 (stdlib Go 1.27.2)
and CVE-2026-78669 (x/net v0.59.0). Latest stable and edge still had the vulnerable
Go runtime. The rebuilt image scan reports Go 1.27.3 / x/net v0.61.0 and zero
HIGH/CRITICAL findings without an ignore file. SMTP capture, API readiness and
SQLite persistence across container restart passed with synthetic data. A second
rehearsal captured mail with the old pinned image and retained it after switching
the same volume to the patched rebuild. Eleven updater tests passed, including
old receipts, fourth-image success, missing/duplicate receipts and mismatched
Mailpit revision/digest rejection. Setup, resolved Compose, source-secret and
workflow syntax checks passed.

The first production rehearsal and initial renderer scan hit Docker ENOSPC.
Authorized unused-cache cleanup allowed an unchanged Node production rehearsal
and renderer scan to pass. The final combined rehearsal hit capacity again;
only task-owned images and unused build cache were removed. The unchanged final
combined `make production-image-rehearsal` then passed, including diagram SVG/PNG
rendering, repository persistence, non-root readability, isolation and secrets.
`make mailpit-image-rehearsal` passed both restart and old-image upgrade cases.
The final rebuilt Mailpit scan also passed without exceptions.
The original failed v0.9.10 tag remains; no v0.9.10 image publication occurred.

Implementation and validation do not authorize tagging, image publication or
production deployment. Current-candidate residual-risk review remains necessary;
v0.9.10 acceptance does not carry forward. The manifest remains pinned to the
last verified published release, v0.9.9.

Local verification is complete for the changed slice. Full hosted Build, CodeQL
and Extended validation must establish final candidate release readiness. No
claim is made that every aggregate release rehearsal was repeated locally.
The public Wiki is unchanged; updated production guidance is staged in
`planning/releases/0.9.11-production-guidance.md` for release publication.
