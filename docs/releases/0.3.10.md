# TekDocs 0.3.10 attachment and inventory workflow evidence

## Outcome

Attachment intake now has explicit storage and scanner adapters, opaque quarantine before promotion, fail-closed cleanup, clean-state metadata, structural hostile-file checks, and integrity verification on every managed read. The built-in scanner is a conservative application defense and is not described as a replacement for a maintained external malware-signature service.

Assets can be linked to exact-workspace assets through the existing typed relationship/RBAC boundary. Authorized operators can also apply an atomic, 100-record maximum hardware-state change or recoverable archive action. Invalid or cross-workspace selections roll back without partially changing inventory.

## Verification

- The hostile-file corpus covers executable/polyglot content, the standard AV test marker, active PDFs, text controls, ZIP traversal, nesting, encryption/expansion constraints, scanner rejection cleanup, promotion integrity, and private checksum-verified reads.
- Backend API tests cover relationship search/create/archive, MSP/client/sibling isolation, atomic bulk rollback, lifecycle evidence, recoverable archive, route-permission inventory, migration reversal/reapplication, and PostgreSQL RLS.
- Frontend component/API tests cover selection, bulk action errors, relationship loading/create/archive, capability denial, keyboard operation, responsive layout, and accessible labels/status.
- Compose, production-image, security, OpenAPI, migration, and full test evidence is recorded at slice closeout.
