# 0.9.7 checkpoint: Valkey readiness visibility

This is a bounded operational checkpoint, not the `0.9.7` release exit.
During local recovery, the Valkey container had stopped on a corrupt append-only
file while the backend readiness endpoint still reported healthy. The original
volume was preserved; a valid snapshot was rehearsed and restored. TekDocs
readiness now checks the configured Redis/Valkey broker and reports a coarse
`valkey` status. The authorized System status page shows that status alongside
the database, renderer and repository checks. A failed broker connection or
persistence write makes readiness unavailable without exposing the broker URL,
exception text or stored values.

The probe is bounded and reuses a connection pool. Non-Redis test or custom
brokers report `not_configured`; this is not a worker-throughput test. It does
not claim recovery of jobs that were not present in the valid snapshot.
The first-wave per-document authority transition and projection-matched rollback
are now implemented behind explicit operator acknowledgement. Portable exports
also render from the accepted Git projection and include commit provenance.
Git-authoritative static publication uses the separate signed evidence, review,
packaging, authorization, and portal-delivery workflow; the legacy publication
endpoint remains blocked so it cannot sign stale PostgreSQL placements.
Generic portable bundles now retain the verified primary-file version chain.
Templates and template-enrolled documents remain deliberately ineligible for
Git authority handoff: PostgreSQL continues to own template and enrollment
operations under the approved architecture. They are not a release-wide blocker
for eligible authored documents. Historical review records whose retained
digest does not match canonical content remain a per-document handoff blocker;
keep those documents PostgreSQL-authoritative or re-review them against the
current canonical Git composition. The primary-file ownership change has
passed its targeted migration/publication tests and the document-migration
release gate. The repository-inclusive recovery rehearsal now
also transitions a migrated document to Git authority, then verifies the
authority marker and Git-backed read after a production-shaped encrypted
backup and network-isolated restore. It covers bounded-write failures; it does
not simulate exhaustion of the host's actual filesystem.
