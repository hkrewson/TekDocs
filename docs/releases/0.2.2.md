# TekDocs 0.2.2 persistent documentation evidence

Date: 2026-08-09

Status: **verified locally.** No push, tag, deployment, Wiki publication, or other external change was performed.

## Delivered scope

- Added workspace-owned `Document` and `Block` records with stable entity identity, canonical Markdown, ordered placements, soft archival, database scope guards, and forced runtime RLS.
- Replaced Documentation placeholders with title-first MSP and organization indexes whose links open the persisted editor.
- Added create, rename, Markdown edit, and archive workflows through versioned APIs protected by the central permission service, normal CSRF/session enforcement, and the maintained route inventory.
- Added explicit `DocumentationListingReference` records so an MSP document can also appear in a client listing without copying content or transferring ownership.
- Made reference provenance visible in the client list and kept edits at the source workspace boundary; cross-listing is discovery/read projection, not an authorization grant.
- Recorded ADR 0020: TekDocs will store provider-neutral credential references rather than credential values, beginning with strictly validated 1Password Private Links.

## Security and ownership boundaries

- Every document route is cataloged and routes authorization through the central policy service; no UI state or hidden control acts as authorization.
- Forced RLS covers documents, blocks, placements, and listing references. Database triggers reject mismatched entity, block, document, tenant, or organization edges.
- An organization reference can target only an MSP-owned document in the same tenant. It cannot reference sibling-owned content or alter the source document's ownership.
- Archive events and reference changes emit value-free audit metadata; stored Markdown is never included in audit payloads.

## Known boundaries

- This slice stores one mutable initial block per newly created document. Immutable revisions, stale-write merge behavior, and diff/history begin in `0.2.3`.
- Live/pinned placement modes, transclusion, backlinks, detach, and entity mentions remain assigned to `0.2.4` and `0.2.5`.
- STATIC publication and immutable artifacts do not exist yet; they remain assigned to `0.2.7` and `0.2.8`.
- The lazy editor bundle remains an owned performance concern under `TD-RISK-013` for `0.2.9`; it is not loaded in the base shell bundle.
- The Compose production check retains its documented local HTTP and OpenAPI enum-name warnings; neither warning weakens the tested application/session boundary.
