# TekDocs 0.0.6 invitation acceptance evidence

Date: 2026-08-07

Status: verified locally; hosted GitHub workflows remain pending publication.

## Delivered scope

- A CSRF-protected public endpoint accepts a pending invitation exactly once and establishes a normal server-side session only after activation commits.
- Acceptance validates passwords through Django and atomically creates the active user, verified primary allauth email, tenant membership, accepted invitation state, and value-free audit event.
- Invitation rows are locked during acceptance. Invalid, malformed, expired, revoked, accepted, mismatched, and concurrently reused tokens share one unavailable response.
- Database constraints align pending token presence and accepted/revoked lifecycle fields. The migration backfills tenant membership for an existing installation owner.
- The browser takes the token only from the URL fragment, removes the fragment immediately, retains secrets only in component memory, clears password fields on submission, and provides accessible activation and unavailable states.
- Installation members can resolve authenticated tenant context, while invitation administration remains installation-owner-only and public allauth signup remains closed.

## Verification

- `make check`: passed Ruff, mypy, migration drift, OpenAPI drift, frontend lint/type checks, 27 frontend unit/component tests, and the production build.
- `make test`: passed 61 backend tests with three PostgreSQL-only concurrency skips and 90.08% aggregate coverage, plus all 27 frontend tests with 87.10% statement coverage.
- `make test-compose`: upgraded the persistent installation, backfilled its owner membership, returned ready status at version `0.0.6`, confirmed SMTP delivery through Mailpit, and passed all 64 backend tests against PostgreSQL with 94.11% aggregate coverage.
- PostgreSQL tests proved exactly one concurrent owner bootstrap, invitation issuance, and invitation acceptance succeeds.
- Acceptance tests cover verified email creation, tenant membership, normal session context, owner-only administration denial, password rollback, CSRF denial, authenticated-user conflict, expiry, revocation, replay, and value-free auditing.
- `make test-e2e`: passed eight Chromium workflows, including activation-fragment removal, unavailable-state and activation accessibility checks, authentication, navigation, and canonical Markdown editing.
- `make security`: passed `pip-audit`, Bandit with zero findings, npm production audit, Gitleaks with no leaks, and blocking High/Critical Trivy scans for the backend, frontend, and pinned Mailpit image with zero findings.
- OpenAPI generation and drift validation passed with the invitation-acceptance contract and version `0.0.6`.
