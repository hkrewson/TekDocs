# TekDocs 0.1.6 structured sites and locations evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- MSP and organization workspaces now have addressable `Site` records with codes, postal address fields, country, timezone, and contact phone metadata.
- Each site owns a hierarchical tree of addressable building, floor, suite, room, office, desk, and area locations. Parent relationships cannot cross a site or workspace, and application plus database validation rejects cycles.
- Scope-specific list, create, detail, update, and archive APIs derive ownership from the URL. Installation-owner plus MFA remains the temporary policy boundary, and audit events never contain site or location values.
- Archiving a site archives its active locations. Archiving a location archives its descendants while preserving historical identities and references.
- People associations may select an active structured site and nested location from the same workspace. Existing location and office text fields remain usable and retain readable snapshots if a structured record is later archived.
- The Sites interface provides search, create/edit/archive workflows, nested hierarchy presentation, responsive controls, explicit loading/empty/error/denial states, and stale-workspace isolation.
- ADR 0009 fixes the hierarchy, ownership, archival, and retained-label contracts for later assets, racks, networks, and diagrams.

## Known boundaries

- Sites and locations describe inventory and placement; they do not grant authorization. Client assignments and custom roles remain later RBAC slices.
- Moving a location between sites is intentionally unsupported. Create a replacement and archive the prior location so historical references are not silently reinterpreted.
- Geocoding, maps, floor plans, racks, custom location kinds, and bulk import remain later domain work.
- Local Compose intentionally permits HTTP and therefore reports Django's HTTPS-redirect deployment warning. The production-image rehearsal enforces the production settings contract.
- PostgreSQL RLS, database-enforced audit immutability, secret-file enforcement, reproducible supply-chain inputs, backups, hosted automation evidence, and the editor bundle warning remain tracked in the engineering risk register.
