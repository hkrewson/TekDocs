# TekDocs 0.1.3 workspace boundary evidence

Date: 2026-08-08

Status: verified locally; hosted GitHub workflows remain pending publication and a pull request.

## Delivered scope

- React Router now owns application navigation, dynamic organization workspace routes, redirects, history, bookmarks, and not-found behavior.
- Active organization titles link to stable `/organizations/{entity-id}` workspaces. Direct loads and refreshes resolve the same server-authorized context.
- The Django workspace resolver returns MSP or organization identity, classifications, and capability hints through explicit `DataScope` values; the browser supplies no tenant ownership.
- Missing, malformed, archived, foreign-tenant, non-member, non-owner, and missing-MFA requests fail without returning organization details.
- The existing organization mutation boundary continues deriving tenant ownership server-side. Organization child domains must adopt the workspace conformance rule as they are introduced.
- A pristine, non-mocked Chromium journey now bootstraps an owner, enrolls real TOTP MFA, creates and opens an organization through the UI, refreshes its route, and verifies the persisted fixture directly in PostgreSQL.
- The local Compose provenance doctor prevents evidence from silently reusing containers created by another checkout. The canonical stack was recreated from this checkout while preserving its named data volumes.
- Frontend gates use an isolated Node 24 container when the host runtime is unsupported.
- The production-target rehearsal verifies proxy-to-Django readiness, migrations, absence of development test tooling, an unprivileged runtime user, and fresh isolated storage.
- The secret-file and production-image plan defines supported file inputs, failure behavior, ownership, rotation expectations, later enforcement releases, and exact-image release proof.

## Defects exposed by the new evidence

- The real browser journey found that a pristine browser did not receive a CSRF cookie from bootstrap status. The endpoint now explicitly establishes the cookie, with a regression assertion.
- The production target found that the OIDC seam relied on `requests` arriving incidentally through development tooling. The allauth social-account runtime extra is now declared directly.
- The upgrade rehearsal found that PID-derived test ports can collide with local services. Upgrade projects now request Docker-assigned host ports and retain unique project names.

## Verification

- `make check` passed version synchronization, Ruff, mypy across 45 source files, migration drift, OpenAPI drift, frontend lint/type checks, and the Node 24 production build.
- `make test` passed 127 backend tests with 91.44% coverage and 58 frontend unit/component tests with 85.9% statement coverage.
- `make test-workspaces` passed 16 workspace/scoping cases against the retained PostgreSQL stack.
- `make test-e2e-live` passed the isolated browser-to-proxy-to-Django-to-PostgreSQL workflow.
- `make clean-install-rehearsal` verified a pristine `0.1.3` installation; `make upgrade-rehearsal` preserved the `0.1.2` identity, MFA, audit, tenant, organization, and classification fixtures through upgrade.
- `make production-image-rehearsal` passed the isolated production-target contract.
- Pip-audit and npm audit reported no known dependency vulnerabilities; Bandit reported no issues; Gitleaks found no leaks; Trivy reported no High or Critical findings in the backend, frontend, or Mailpit images.
- The ordinary Compose stack reports version `0.1.3`, passes its provenance check, and retained the existing bootstrapped `Tek-Cetera` tenant after normalization.

## Known boundaries

- Workspace selection does not yet include the searchable, bounded shell switcher, classification-aware navigation, independent-tab history exercises, or server-side organization search. Those form `0.1.4` and `TD-RISK-012`.
- Organization administration and workspace access remain owner-plus-MFA only until the policy catalog and scoped RBAC releases.
- PostgreSQL RLS is designed but inactive; application scoping and database integrity guards are not represented as a substitute for `TD-RISK-002`.
- The editor bundle warning, user-owned uncommitted editor/example work, reproducible Python/runtime inputs, hosted CI proof, database-enforced audit immutability, backup/key recovery, and structured-log work retain their milestones in `docs/ENGINEERING_RISKS.md`.
