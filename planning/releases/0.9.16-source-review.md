# 0.9.16 source review

Maintainer-directed AI review of `v0.9.15...65302e4` and the subsequent acceptance
and release-preparation changes. The code-review skill runs separate Standards
and Spec reviews. This is not an independent human security assessment,
penetration test, certification or exhaustive audit.

The runtime delta covers publication assessment/import/authority handoff, v5
publication guards and signing, immutable predecessor reads, retained recovery,
and the interface. The later working delta adds the real browser gate and its
source-cache correction. Normal release metadata advances to 0.9.16.

## Standards

The immutable runtime delta had **zero hard documented-standard findings**.
Central policy, active-actor/MFA checks, tenant/client boundaries, pinned Git
source, existing cryptography, append-only records and retained custody remain
in place. Migration 0196 extends the normal Django schema authority. Readiness
does not resolve the legacy draft. Interface copy, error/draft states and safe
Markdown rendering follow the existing contracts. Removing tracked agent files
implements the maintainer's explicit privacy instruction.

Review of the new harness identified two P2 failure-path findings: cleanup
stopped the fixture before Django could drop its generated database, and an
early startup failure could retain a previous passed summary. A controlled
interruption during database initialization reproduced both: the owned database
and previous passed summary remained. The experiment removed only its database.
Cleanup now permits bounded graceful teardown, interrupts its recorded runner
when needed, and explicitly removes only its generated test database. A new
attempt clears old evidence; the combined summary includes server verification
and cannot pass after server-side failure. The same interruption replay returned
143 with neither database nor summary left behind. Final normal acceptance also
passed. Follow-up Standards review found both findings resolved.

One further P2 portability finding was reproduced with native Linux UIDs: a
host-owned `0700` handoff directory denied the normal service user access.
The invocation directory now retains its host owner and grants only the service
group access (`2770`). Session input stays `0600`; completion status is group
readable, host failure markers replace atomically, and only the sanitized
summary becomes host readable. The Linux UID replay verifies service access,
controller denial of private input and status exchange. Follow-up Standards
review found this issue resolved without running the fixture server as root.

No new runtime dependency, permission grant, signing scheme or unsafe HTML sink
is added by preparation. The generated-session IPC is temporary/private and
excluded from retained evidence; browser traces, screenshots and videos are off.
The final server test observes actual HTTP connections with `SELECT current_user`
and requires the nonempty role set to equal the constrained runtime role.

## Spec

The immutable interface delta had one P2 finding: correction controls depended
on the currently visible document collection, despite the specification allowing
publication-history links and correction of each retained version.

Reproduction used the real server/browser: the search returned zero records, the
retained publication loaded through its direct link, and **Publish correction**
was absent. The fix keeps the fetched authorized document independently of the
collection and guards it by Workspace identity. The unchanged browser assertion
then passed, including the legacy-to-Git correction. The follow-up Spec review
found the original issue resolved and no new concrete mismatch in that patch.

Broader templates/files/keys/client-delivery work is deliberately deferred;
neither release preparation nor a green gate marks those requirements complete.
