# 0.9.7 progress: exact Git publication-source evidence

Date: 2026-10-07. Application version remains `0.9.6`. This is the first
internal foundation for [issue #106](https://github.com/hkrewson/TekDocs/issues/106),
not a `0.9.7` release or an authority handoff.

## Bounded result

`freeze_git_document_dependencies` produces a deterministic, value-free proof
of one repository document's accepted commit, root Markdown blob, and ordered
audience-visible live or pinned fragment blobs. It records path, commit, blob
ID, exact-byte SHA-256, and composition identity. It re-reads Git content,
recomputes the bounded composition, checks the current index, and fails closed
on index lag, projection drift, or missing pinned source objects. There is no
new route, database schema, or stored publication format in this step.

The second internal foundation provides `pinned_git_document_dependencies`, a
transactional source-proof context for a future repository publisher. It holds
the managed Git lock before the repository database row lock, recomputes the
proof under both locks, and rechecks accepted/indexed identities and Git head
before commit. A concurrent authoring commit waits until the context ends;
an exception or state change rolls back the attempted retention. It also works
inside the authenticated request's outer transaction: the repository row lock
persists until that transaction commits.

The third internal foundation retains one composed Markdown snapshot and the
exact Git dependency proof in a separate signed, append-only, exact-Workspace
record. It uses the deployment publication signing key and verifies the
retained text, manifest, source identity and trusted key without consulting
the live repository. PostgreSQL insertion guards, forced RLS, and update/delete
triggers protect the record below the service layer. Publisher permission and
MFA are required. This is evidence for a future repository STATIC path, not
a routed, approved, downloadable or portal-visible publication.

## Validation and remaining work

The synthetic PostgreSQL/Docker composition suite covers nested pins, live
sources, audience filtering, exact SHA-1 Git blob identity, deterministic
repeat, projection tampering, accepted-head lag and missing pinned objects.
The broader `make test-content-composition` gate passed locally against the
signed-evidence foundation and its predecessors. Repository-wide `make check`
also passed for this slice, including frontend tests/build, backend lint and
typing, migration drift, and OpenAPI. The lock test uses separate PostgreSQL
connections to verify that a concurrent writer cannot advance the head while
the retention context is open. A further race test proves the database row
remains pinned until an authenticated request's outer transaction commits.
Rollback and stale-index rejection are covered. Evidence tests cover publisher
MFA denial and allow, exact-client and foreign-tenant runtime isolation,
signature and retained-byte tampering, database-level insert/update/delete
guards, verification after the live head advances, and an `0167`→migration-head
upgrade with forced RLS restored in `finally`.

The existing STATIC publisher remains database-authored. Integration of this
evidence with approval, artifacts and distribution, attachments, editable and
sanitized exports, templates/monitored sources, client listing/portal parity,
encrypted repository-inclusive
backup/restore, and recovery fault rehearsals remain open in `0.9.7`. No
production cutover, deployment, or hosted CI result is claimed here.
